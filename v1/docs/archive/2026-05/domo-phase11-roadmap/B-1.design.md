# Phase 11 B-1 Design — Admin ML 실험 관리 UI (`/admin/experiments`)

> **Summary**: K-8(Phase 10)에서 완성된 `ml_experiments` 백엔드 API 위에, admin이 A/B
> 실험을 생성·조회·분석할 수 있는 프론트엔드 페이지를 추가한다. PostHog Insights
> iframe 임베드(OQ-2 권장)로 자체 차트 구현 없이 결과 분석을 제공하며, AdminShell에
> "ML Operations" 그룹을 신설해 experiments + diversity-config 진입점을 통합한다.

---

## 1. 목표 & Acceptance Criteria

### 목표

| # | 목표 | 근거 |
|---|------|------|
| 1 | Admin이 `/admin/experiments`에서 실험 목록을 확인하고 생성할 수 있음 | K-8 백엔드 완성, 프론트 미구현 상태 해소 |
| 2 | PostHog Insights iframe 임베드로 결과 분석 0 개발 비용 달성 | OQ-2 권장 default 채택 |
| 3 | 실험 생성 시 50:50 분배 기본값 적용, 14일 자동 종료 옵션 제공 | OQ 결정사항 반영 |
| 4 | AdminShell에 "ML Operations" 그룹 신설 — B-2(diversity-config)와 통합 진입점 | 누락 메뉴 해소 (Admin 콘솔 격차 7개 중 2개 Wave B) |
| 5 | tsc 0 errors, 5 locale i18n 커버리지 | Phase 11 전체 품질 기준 준수 |

### Acceptance Criteria

- [ ] `/admin/experiments` 진입 → 실험 목록 (running/paused/completed 상태 포함) 정상 표시
- [ ] 실험 카드: 이름, 가설, 분배 비율, 시작일/종료일, status, target_metric, variant별 assignment 수 표시
- [ ] "신규 실험 생성" 모달: name/hypothesis/variant_distribution(기본 50:50)/target_metric 입력 → POST 성공
- [ ] 실험 일시정지(paused) 및 종료(completed) 상태 변경 버튼 동작 확인
- [ ] PostHog Insights iframe 임베드 표시 확인 (`NEXT_PUBLIC_POSTHOG_INSIGHTS_BASE_URL` 설정 시)
- [ ] fallback "PostHog Insights 열기" 외부 링크 동작 확인 (env 미설정 시)
- [ ] AdminShell "ML Operations" 그룹 — `/experiments`, `/diversity-config` 항목 표시 및 링크 동작 확인
- [ ] 5 locale i18n 키(`admin.experiments.*`) 표시 확인
- [ ] tsc 0 errors, lint 0 errors

#### `ExperimentCard.tsx`

props 타입:

```typescript
interface ExperimentCardProps {
  experiment: Experiment;
  onStatusChange: (name: string, status: "paused" | "completed") => Promise<void>;
}
```

표시 항목:
- 실험 이름 (`name`) + status 배지 (running=녹색, paused=주황, completed=회색, draft=파란색)
- 가설 (`hypothesis`) — 최대 2줄, 더보기 토글
- 분배 비율 시각화: `variant_distribution` JSONB → 두 컬럼 비율 표시
- 시작일(`started_at`) / 종료일(`ended_at` 또는 "진행 중") / `target_metric`
- 운영 일수: `days_running` (API 결과에서 가져오거나 클라이언트 계산)
- `assignment_counts` variant별 사용자 수 (v1: N명 / v2: M명)
- 액션 버튼:
  - "결과 분석 열기/닫기" → `PostHogEmbed` 패널 토글
  - "일시정지" (running 상태만 활성) → `onStatusChange(name, "paused")`
  - "종료" (running/paused 상태) → confirm 다이얼로그 후 `onStatusChange(name, "completed")`

#### `CreateExperimentModal.tsx`

- shadcn/ui `Dialog` 사용
- 폼 필드:
  - `name`: 필수, pattern `^[a-z0-9_]+$` (백엔드 UNIQUE 제약 준수)
  - `hypothesis`: optional, `<textarea>`
  - `variant_distribution`: v1/v2 숫자 입력 → 합계 100% 검증
  - `target_metric`: `<select>` (feed_ctr / session_duration / sponsor_cvr / 직접입력)
  - `status`: radio (draft / running), 기본값 `running`
  - 자동 종료 체크박스: 14일 후 completed (UI only 표시, 실제 cron은 백엔드 별도 구현)
- 제출: `createExperiment()` 호출 → 성공 시 모달 닫기 + 목록 refetch
- 중복 이름 409 Conflict 에러 처리: 인라인 에러 메시지 표시

## 5. PostHog 임베드 전략

### 5-1. 환경변수

Admin 콘솔 `.env.local` (또는 배포 환경 env):

```env

NEXT_PUBLIC_POSTHOG_INSIGHTS_BASE_URL=https://app.posthog.com
```

백엔드 `admin_experiments.py`의 `_POSTHOG_HOST` 환경변수와 별도로 관리.
프론트엔드는 `NEXT_PUBLIC_` 접두어로 클라이언트 번들에 노출.

### 5-2. iframe 보안 처리

```tsx
<iframe
  src={embedSrc}
  title={`PostHog Insights — ${experimentName}`}
  sandbox="allow-scripts allow-same-origin allow-popups allow-forms"
  referrerPolicy="strict-origin-when-cross-origin"
  className="w-full rounded-md border border-admin-border"
  style={{ height: "480px" }}
/>
```

- `allow-scripts`: PostHog 대시보드 JavaScript 실행 허용
- `allow-same-origin`: PostHog 쿠키/세션 유지 허용
- `allow-popups`: 외부 링크 클릭 시 새 탭 허용
- `allow-forms`: PostHog 대시보드 내 필터 조작 허용
- `allow-top-navigation` 제외: Admin 콘솔 URL 변경 공격 차단

### 5-3. CSP 이슈 대응

PostHog 측 CSP가 iframe 삽입을 차단할 경우 fallback 자동 전환:

```tsx
// iframe onError 핸들러
const [embedFailed, setEmbedFailed] = useState(false);

if (embedFailed || !baseUrl) {
  return <ExternalLinkFallback url={posthogInsightsUrl} />;
}

return (
  <iframe
    onError={() => setEmbedFailed(true)}
    src={embedSrc}
    ...
  />
);
```

export type ExperimentStatus = "draft" | "running" | "paused" | "completed";

### 6-2. `lib/api.ts` 추가 함수 (3개)

기존 admin api.ts에 추가:

```typescript
// ── Experiments API ─────────────────────────────────────────────────────────

export async function listExperiments(): Promise<{ data: Experiment[] }> {
  return apiFetch("/api/admin/experiments");
}

export async function createExperiment(
  payload: CreateExperimentPayload
): Promise<{ data: Experiment }> {
  return apiFetch("/api/admin/experiments", {
    method: "POST",
    body: JSON.stringify(payload),
  });
}

export async function getExperimentResults(
  name: string
): Promise<{ data: ExperimentResults }> {
  return apiFetch(`/api/admin/experiments/${encodeURIComponent(name)}/results`);
}
```

참고: 상태 변경(paused/completed)은 `POST /api/admin/experiments`로 name 충돌 409가 발생하므로, 백엔드에서 PATCH endpoint 미구현 상태. B-1 scope에서는 상태 변경 UI 버튼을 표시하되, 실제 API 연동은 백엔드 PATCH 구현 후 활성화. 현재는 버튼 클릭 시 "백엔드 PATCH 미구현" 토스트 메시지 표시 후 Phase 11 B-1 완료 보고서에 후속 작업으로 기록.

> **참고**: 백엔드 `admin_experiments.py`의 `POST /admin/experiments`는 name UNIQUE 위반 시 409를 반환하므로, 상태 변경(pause/complete)을 위한 별도 `PATCH /admin/experiments/{name}` endpoint가 필요하다. B-1에서는 UI만 구현하고, 해당 PATCH endpoint는 백엔드 팀과 조율 후 추가 구현.

## 8. 테스트 (수동)

### 8-1. 기본 플로우

1. `/admin/experiments` 진입
   - 기대: 실험 목록 표시 (K-8 seed 데이터 `feed_v2_rollout` 포함)
   - 확인: 이름, 가설, 분배 비율, status 배지, assignment_counts 정상 표시

2. 신규 실험 생성
   - "신규 실험 생성" 버튼 클릭 → 모달 열기
   - name: `test_experiment_b1`, 분배 50:50, status: draft
   - "실험 생성" 클릭 → 201 Created → 목록 갱신 확인

3. 중복 이름 에러
   - name: `feed_v2_rollout` (기존 존재) → "실험 생성" 클릭
   - 기대: 409 Conflict 인라인 에러 메시지 표시

4. 결과 분석 패널
   - `feed_v2_rollout` 카드 → "결과 분석 열기" 클릭
   - `NEXT_PUBLIC_POSTHOG_INSIGHTS_BASE_URL` 설정 시: iframe 표시
   - 미설정 시: "PostHog Insights 열기 ↗" 링크 + 안내 문구 표시

5. 상태 변경 (백엔드 PATCH 구현 후 활성화)
   - running 실험 → "일시정지" 버튼 클릭 → 상태 paused 변경 확인
   - "실험 종료" 버튼 클릭 → confirm 다이얼로그 → 상태 completed 변경 확인

6. AdminShell 메뉴
   - 사이드바 "ML Operations" 그룹 표시 확인
   - "A/B 테스트 (K-8)" 클릭 → `/experiments` 이동 확인
   - "다양성 설정 (K-2)" 클릭 → `/diversity-config` 이동 확인
   - 2FA 미완료 admin → `/settings/totp-setup` 리다이렉트 확인 (기존 로직 회귀)

### 8-2. 접근성 체크

- "신규 실험 생성" 버튼: `aria-label="새 A/B 실험 생성"`
- 모달: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` 연결
- iframe: `title` 속성 필수 (스크린 리더 식별)
- status 배지: 색상만으로 구분하지 않고 텍스트 병기
- 키보드 네비게이션: 모달 내 Tab 순환, Esc → 모달 닫기

### 8-3. 회귀 테스트

- 기존 AdminShell 경로 모두 정상 동작 확인:
  - `/dashboard`, `/users`, `/featured-artist-queue`, `/ai-collections-queue`,
    `/settings/passkeys`, `/settings`
- `STANDALONE_ROUTES`, `ALLOW_WITHOUT_2FA` 로직 영향 없음 확인
