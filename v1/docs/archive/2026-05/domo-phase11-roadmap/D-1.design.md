# Phase 11 D-1 Design — 전역 키보드 단축키 시스템

> **Summary**: 가이드 v1에서 12개 단축키를 명시했으나 실제 구현된 것은 모달 ESC + ImageEditor
> 1/2/3/4 도구 전환뿐이었다. Phase 11 D-1에서는 사용자 OQ 결정에 따라 가장 사용 빈도가 높은
> 3+1 단축키(j/k 피드 내비게이션, ⌘S 임시저장, ? 도움말)를 우선 구현하고, 재사용 가능한
> `useGlobalHotkeys` hook과 `KeyboardShortcutsHelp` 모달을 기반 인프라로 확립한다.

- [ ] 피드 페이지(`/`, `/feed`)에서 j 키 → 다음 게시물로 smooth scroll + 포커스 이동 확인

## 2. Hook 설계 — `useGlobalHotkeys`

### 파일

`v1/frontend/src/lib/hooks/useGlobalHotkeys.ts`

### 타입 정의

```ts
type HotkeyHandler = (e: KeyboardEvent) => void;

interface HotkeyDefinition {
  /** 단일 키 문자열. 예: "j", "k", "?", "s" */
  key: string;
  /** 수정자 키. "cmd"는 macOS ⌘ + Windows Ctrl 모두 처리 */
  modifier?: "cmd" | "ctrl" | "shift";
  /** 키 핸들러 */
  handler: HotkeyHandler;
  /**
   * false 로 설정하면 이 단축키를 등록하지 않는다.
   * route별 조건부 활성화에 사용. default: true
   */
  enabled?: boolean;
  /**
   * true(default)이면 input/textarea/contentEditable 포커스 시 이 핸들러를 건너뛴다.
   * ⌘S 처럼 의도적으로 폼 안에서도 동작해야 할 경우 false 로 오버라이드.
   */
  preventInInputs?: boolean;
}

export function useGlobalHotkeys(hotkeys: HotkeyDefinition[]): void;
```

### 구현 로직 요약

```
mount 시 단일 keydown 핸들러를 window 에 등록.
hotkeys 배열 순회:
  1. definition.enabled === false → 건너뜀
  2. preventInInputs !== false && shouldIgnoreHotkey(e.target) → 건너뜀
  3. modifier 체크:
     - "cmd"  → (macOS) e.metaKey || (non-Mac) e.ctrlKey
     - "ctrl" → e.ctrlKey (modifier 없이 Ctrl만 원할 때)
     - "shift"→ e.shiftKey
  4. e.key.toLowerCase() === definition.key.toLowerCase() → handler(e) 호출
unmount 시 이벤트 제거.
hotkeys 배열 변경 시 핸들러 재등록 (useEffect deps: [hotkeys]).
```

### 입력 포커스 차단 헬퍼

```ts
function shouldIgnoreHotkey(target: EventTarget | null): boolean {
  if (!(target instanceof HTMLElement)) return false;
  const tag = target.tagName.toLowerCase();
  if (tag === "input" || tag === "textarea" || tag === "select") return true;
  if (target.isContentEditable) return true;
  return false;
}
```

### 기존 패턴과의 비교

| 기존 | D-1 이후 |
|------|---------|
| PublishDrawer: `useEffect` → `window.addEventListener("keydown", ...)` 직접 | ESC 패턴 유지 (Drawer 자체 로컬 로직으로 충분) |
| ImageEditor: `useEffect` → 1/2/3/4 도구 전환 keydown | 로컬 유지 (모달 내부 한정 단축키) |
| 전역 j/k/⌘S/? | 신규 `useGlobalHotkeys` 로 일원화 |

> 판단 근거: PublishDrawer와 ImageEditor의 단축키는 해당 컴포넌트가 마운트된 경우에만
> 유효한 로컬 단축키이므로 별도 마이그레이션 없이 유지한다. 전역 단축키만 hook으로 통합.

## 5. j/k 피드 내비게이션

### 활성 조건

- `AppShell` 에서 현재 pathname 확인: `pathname === "/" || pathname === "/feed"`
- `usePathname()` (next/navigation) 사용
- 해당 경로가 아닌 경우 `enabled: false` 로 단축키 비등록

### 동작 명세

```
현재 화면 중앙에 가장 가까운 게시물 카드를 "활성 카드"로 정의.

j 키:
  1. 활성 카드 다음 카드 존재 여부 확인
  2. 존재하면 → element.scrollIntoView({ behavior: "smooth", block: "center" })
  3. 해당 카드에 focus() — tabIndex={0} 보장 필요 (FeedItem 수정 없이 data-feed-item 속성으로 쿼리)
  4. 마지막 카드에서 → 무동작 (시각 피드백 없음)

k 키:
  1. 활성 카드 이전 카드 존재 여부 확인
  2. 존재하면 → scrollIntoView + focus
  3. 첫 카드에서 → 무동작
```

### DOM 쿼리 전략

```ts
// 피드 카드에 data-feed-item 속성 부여 (FeedItem 수정 또는 피드 페이지 wrapper)
const cards = Array.from(
  document.querySelectorAll<HTMLElement>("[data-feed-item]")
);

function getActiveIndex(cards: HTMLElement[]): number {
  const centerY = window.innerHeight / 2;
  let closest = 0;
  let minDist = Infinity;
  cards.forEach((card, i) => {
    const rect = card.getBoundingClientRect();
    const cardCenterY = rect.top + rect.height / 2;
    const dist = Math.abs(cardCenterY - centerY);
    if (dist < minDist) { minDist = dist; closest = i; }
  });
  return closest;
}
```

### AppShell 수정 포인트

```tsx
// AppShell 내부 — pathname 감지 + j/k 단축키 등록
const pathname = usePathname();
const isFeedPage = pathname === "/" || pathname === "/feed";

const navigateFeed = useCallback((direction: "next" | "prev") => {
  const cards = Array.from(
    document.querySelectorAll<HTMLElement>("[data-feed-item]")
  );
  if (cards.length === 0) return;
  const active = getActiveIndex(cards);
  const target = direction === "next" ? active + 1 : active - 1;
  if (target < 0 || target >= cards.length) return;
  cards[target].scrollIntoView({ behavior: "smooth", block: "center" });
  cards[target].focus({ preventScroll: true });
}, []);

useGlobalHotkeys([
  {
    key: "j",
    handler: () => navigateFeed("next"),
    enabled: isFeedPage && !helpOpen,
  },
  {
    key: "k",
    handler: () => navigateFeed("prev"),
    enabled: isFeedPage && !helpOpen,
  },
  {
    key: "?",
    handler: () => setHelpOpen(true),
    enabled: !helpOpen,
  },
]);
```

## 6. ⌘S 임시저장

### 활성 범위

- `/posts/new/page.tsx` — `CreatePostPageInner` 컴포넌트 내부
- 전역 AppShell 에서 등록하지 않음 (route별 책임 분리)

### 구현

```tsx
// CreatePostPageInner 내부
useGlobalHotkeys([
  {
    key: "s",
    modifier: "cmd",       // macOS ⌘S + Windows/Linux Ctrl+S 자동 처리
    handler: (e) => {
      e.preventDefault(); // 브라우저 기본 "저장" 다이얼로그 차단
      handleManualSave();
    },
    preventInInputs: false, // 등록 폼에서도 의도적으로 동작해야 함
  },
]);
```

### modifier: "cmd" 처리 로직 (hook 내부)

```ts
case "cmd":
  if (!(e.metaKey || e.ctrlKey)) return; // macOS: metaKey, Windows/Linux: ctrlKey
  break;
```

### 사용자 경험

- 저장 성공 시 기존 autosave 토스트 메시지 재활용 (별도 UI 추가 없음)
- 저장 중(pending) 상태에서 재호출 시 `handleManualSave` 내부 guard 로 중복 방지
  (기존 구현이 `me` null check로 guard하며, saveToServer 병렬 호출 방지는 현 코드 구조 유지)

## 7. 입력 폼 포커스 차단 상세

### `shouldIgnoreHotkey` 전체 구현

```ts
function shouldIgnoreHotkey(target: EventTarget | null): boolean {
  if (!(target instanceof HTMLElement)) return false;
  const tag = target.tagName.toLowerCase();
  // 표준 입력 요소
  if (tag === "input" || tag === "textarea" || tag === "select") return true;
  // contentEditable (리치 텍스트 에디터 포함)
  if (target.isContentEditable) return true;
  return false;
}
```

### 예외 처리 매트릭스

| 단축키 | `preventInInputs` | 동작 |
|--------|:-----------------:|------|
| j | true (default) | input 포커스 시 비활성 |
| k | true (default) | input 포커스 시 비활성 |
| ? | true (default) | input 포커스 시 비활성 |
| ⌘S | **false** | 등록 폼 포커스 중에도 활성 |

### 모달 열린 동안 처리

- `helpOpen === true` 인 경우 j/k/? 모두 `enabled: false`
- ESC 닫기는 `Dialog` 내부 처리 (hook 미관여)
- 도움말 모달 내부 포커스는 `Dialog` 기본 focus trap 으로 처리

```tsx
export function AppShell({ children }: { children: React.ReactNode }) {
  const { me } = useMe();
  const { wizardStep, finish } = useOnboarding();
  const pathname = usePathname();
  const [helpOpen, setHelpOpen] = useState(false);

    if (cards.length === 0) return;
    const activeIdx = getActiveIndex(cards);
    const targetIdx = direction === "next" ? activeIdx + 1 : activeIdx - 1;
    if (targetIdx < 0 || targetIdx >= cards.length) return;
    cards[targetIdx].scrollIntoView({ behavior: "smooth", block: "center" });
    cards[targetIdx].focus({ preventScroll: true });
  }, []);

  useGlobalHotkeys([
    { key: "j", handler: () => navigateFeed("next"), enabled: isFeedPage && !helpOpen },
    { key: "k", handler: () => navigateFeed("prev"), enabled: isFeedPage && !helpOpen },
    { key: "?", handler: () => setHelpOpen(true), enabled: !helpOpen },
  ]);

  return (
    <CognitiveSimpleModeProvider>
      <SkipLink />
      <div className="flex min-h-screen">
        <Sidebar />
        <div id="main-content" className="flex-1 min-w-0 pb-16 md:pb-0">
          {children}
        </div>
      </div>
      <MobileTabBar />
      {showWizard && <OnboardingWizard onClose={handleWizardClose} />}
      <KeyboardShortcutsHelp open={helpOpen} onClose={() => setHelpOpen(false)} />
    </CognitiveSimpleModeProvider>
  );
}
```

## 11. 위임 Agent 및 구현 순서

### 담당 Agent

**frontend-architect**: 전 구현 담당

### 구현 순서

```
Step 1. useGlobalHotkeys hook 작성
        → 타입 정의, shouldIgnoreHotkey, 이벤트 등록/해제

Step 2. KeyboardShortcutsHelp 모달 작성
        → Dialog 기반, Kbd 내부 컴포넌트, i18n 연결

Step 3. i18n 5 locale 추가
        → ko/en/ja/zh/es — keyboardShortcuts.* 10 keys

Step 4. AppShell 수정
        → usePathname, helpOpen state, navigateFeed, useGlobalHotkeys 등록
        → KeyboardShortcutsHelp 렌더

Step 5. posts/new/page.tsx 수정
        → ⌘S → handleManualSave 연결

Step 6. 수동 테스트 시나리오 1~12 검증
        → tsc 0 errors 확인
```

### 주의 사항

- `usePathname` 은 Next.js App Router 전용. `AppShell` 이 이미 Client Component (`"use client"`) 이므로 추가 wrapper 불필요.
- `FeedItem` 컴포넌트에 `data-feed-item` 속성 추가 또는 피드 페이지 렌더 루프에서 wrapper div에 속성 부여. 기존 `FeedItem` props 인터페이스를 변경하지 않고 피드 페이지(`/feed/page.tsx`) 의 `<FeedItem>` wrapper `<div data-feed-item>` 으로 처리하는 방식을 권장한다.
- `tabIndex={0}` 은 `data-feed-item` wrapper div에 함께 부여해야 `focus()` 가 동작한다.
- ⌘S `preventInInputs: false` 설정 시 hook 내부에서 `shouldIgnoreHotkey` 체크를 건너뛰는 분기 처리 필요.
- `KeyboardShortcutsHelp` 에서 ESC 처리는 shadcn/ui `Dialog` 기본 동작(`onOpenChange`)에 위임 — 별도 keydown 리스너 추가 금지 (중복 등록 방지).
