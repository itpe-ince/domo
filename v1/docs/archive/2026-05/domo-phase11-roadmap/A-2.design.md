# Phase 11 A-2 Design — Admin AI 컬렉션 검수 큐 UI

> **Summary**: Phase 10 K-7에서 구현된 AI 큐레이션 컬렉션 백엔드(매주 월요일 09:00 UTC 자동 생성, alembic 0083)의
> Admin 검수 큐 프론트엔드를 구현한다. `/admin/ai-collections-queue` 신규 페이지에서 운영자가
> LLM 생성 컬렉션을 검토하고 발행/편집/아카이브/거부 액션을 수행할 수 있게 한다.
> autopublish OFF 정책 유지 — 모든 AI 생성 컬렉션은 admin 명시 승인 후 `/explore/collections`에 노출된다.

---

## README 비전 연결

> "컬렉터들한테는 회비 1년에 10분씩" — Editor's Pick 컬렉션 운영자 검수를 통해
> 주간 큐레이션 품질을 보장하고, 컬렉터의 탐색 경험 가치를 유지한다.

> "히스토리를 두세 개 만든다" — 운영자 편집 기능으로 AI 생성 스토리에
> 편집자의 관점을 더해 언론·SNS 확산 가능한 큐레이션 내러티브를 완성한다.

## 1. 목표 & Acceptance Criteria

### 1-1. 목표

| # | 목표 | 근거 |
|---|------|------|
| 1 | Admin 콘솔에서 AI 생성 컬렉션 검수 UI 제공 | 현재 DB 직접 조작 의존 — 운영 차단 상태 해제 |
| 2 | 발행/편집/아카이브/거부 액션 원클릭 처리 | 평균 검수 시간 ≤ 5분 목표 |

| 4 | 주간 드롭다운으로 이력 확인 | 발행률 KPI 추적 (운영 4주 후 ≥ 60%) |
| 5 | A-1 Curation 그룹과 AdminShell 통합 | 메뉴 그룹 충돌 없이 단일 PR 또는 Edit 처리 |

### 1-2. Acceptance Criteria

- [ ] `/admin/ai-collections-queue` 페이지 접근 → 이번 주 generating/pending 컬렉션 목록(최대 5개) 표시
- [ ] 주간 드롭다운(최근 8주) 선택 → 해당 주 컬렉션 목록 갱신
- [ ] 카드 내 locale 토글(ko/en/ja/zh/es) → 해당 locale 제목/설명 표시
- [ ] 발행 버튼 → `POST /api/admin/ai-collections/{id}/publish` → 카드 상태 "발행됨" 전환
- [ ] 편집 모달 → 제목/설명 수정 → 저장 → `PATCH /api/admin/collections/{id}` 호출 확인
- [ ] 아카이브 버튼 → `POST /api/admin/ai-collections/{id}/archive` → 카드 상태 "보관됨" 전환
- [ ] 거부 버튼 → 사유 입력 필수(비어있으면 제출 불가) → `DELETE /api/admin/collections/{id}` → 카드 제거
- [ ] AdminShell Curation 그룹에 "AI 컬렉션 검수" 메뉴 표시 및 활성화
- [ ] 2FA 미완료 admin → `/settings/totp-setup` 리디렉트 (기존 패턴 동일)
- [ ] tsc 0 errors, lint 0 errors

## 2. Architecture

### 2-1. 데이터 플로우

```
[매주 월요일 09:00 UTC]
  ai_curation_cron_loop() — Phase 10 K-7 cron (23번째 worker)
        |
        v
  ai_collections (status='generating') — alembic 0083
        |
        v
  GET /api/admin/ai-collections/queue?week_start={date}
        |
  [Admin 콘솔 — A-2 신규 페이지]
        |
   ┌────┴──────────────────────────┐
   |                               |
   v                               v
발행(Publish)                  편집(Edit)
POST /publish                  PATCH /{id}
status='published'             title/description 업데이트
        |                      백엔드 5 locale 재번역
        v                               |
  /explore/collections         title_translations 갱신
  (공개 노출)                          |
                                        v
                               아카이브(Archive)
                               POST /archive
                               status='archived'

거부(Reject)
DELETE /admin/collections/{id}
사유 필수 → 로그 기록 후 완전 삭제
```

### 2-2. 권한

- `require_admin_with_2fa` (백엔드 의존성 — 변경 없음)
- 프론트엔드: AdminShell의 `needsSecondFactor()` 체크 → 미등록 시 `/settings/totp-setup`
- 401/403 응답 → 기존 `apiFetch` 에러 처리 패턴 동일

### 2-3. 백엔드 API 매핑 (변경 없음)

| 메서드 | 경로 | 기존 구현 파일 | 사용 목적 |
|--------|------|----------------|---------|
| GET | `/api/admin/ai-collections/queue` | `admin_ai_collections.py` | 검수 대기 목록 (week_start 파라미터 추가 필요 — 백엔드 팀 확인) |
| POST | `/api/admin/ai-collections/{id}/publish` | `admin_ai_collections.py` | 발행 |
| POST | `/api/admin/ai-collections/{id}/archive` | `admin_ai_collections.py` | 아카이브 |
| PATCH | `/api/admin/collections/{id}` | `collections.py` 또는 신규 | 편집 + 재번역 트리거 |
| DELETE | `/api/admin/collections/{id}` | `collections.py` 또는 신규 | 완전 삭제 + 사유 로그 |

> 주의: 현재 `admin_ai_collections.py`의 GET `/queue`는 `week_start` 쿼리 파라미터가 없다.
> A-2 Do 단계에서 백엔드에 `?week_start={date}` 파라미터 추가를 요청하거나,
> 프론트엔드에서 `generated_at` 기준 필터링으로 우회 처리한다.

### 3-2. 카드 상태별 시각 처리

| status | border | 상태 텍스트 | 액션 버튼 |
|--------|--------|-----------|---------|
| `generating` | `border-gray-300` (회색) | "생성 중..." (spinner) | 모두 비활성 (disabled) |

### 4-2. useAICollectionsQueue 핵심 로직

```typescript
// lib/hooks/useAICollectionsQueue.ts

export function useAICollectionsQueue() {
  const [selectedWeek, setSelectedWeek] = useState<string>(currentWeekStart());
  const [collections, setCollections] = useState<AdminAiCollection[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const load = useCallback(async (weekStart: string) => {
    setLoading(true);
    setError(null);
    try {
      const data = await fetchAICollectionsQueue(weekStart);
      setCollections(data.items);
    } catch (e) {
      setError("목록을 불러오지 못했습니다.");
    } finally {
      setLoading(false);
    }
  }, []);

  useEffect(() => { load(selectedWeek); }, [selectedWeek, load]);

  const handlePublish = async (id: string) => {
    await publishCollection(id);
    setCollections(prev =>
      prev.map(c => c.id === id ? { ...c, status: "published" } : c)
    );
  };

  const handleArchive = async (id: string) => {
    await archiveCollection(id);
    setCollections(prev =>
      prev.map(c => c.id === id ? { ...c, status: "archived" } : c)
    );
  };

  const handlePatch = async (id: string, patch: { title?: string; description?: string }) => {
    const updated = await patchCollection(id, patch);
    setCollections(prev =>
      prev.map(c => c.id === id ? { ...c, ...updated } : c)
    );
  };

  const handleReject = async (id: string, reason: string) => {
    await rejectCollection(id, reason);
    setCollections(prev => prev.filter(c => c.id !== id));
  };

  return {
    selectedWeek, setSelectedWeek,
    collections, loading, error,
    handlePublish, handleArchive, handlePatch, handleReject,
  };
}
```

