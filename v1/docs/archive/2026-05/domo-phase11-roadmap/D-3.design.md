**작성일**: 2026-05-08

## 1. 목표 & AC (Acceptance Criteria)

### 목표
Google OAuth만 지원하던 Domo에 이메일+비밀번호 인증을 추가하여 가입 다양성 확보.  
신흥 지역(동남아시아, 라틴아메리카, 동유럽) 사용자 중 Google 계정이 없는 경우 대응.

### OQ 확정 결정
| 항목 | 결정 |
|------|------|
| 우선순위 | 이메일+비밀번호 1순위 (GitHub/매직링크 Phase 12) |
| 이메일 인증 | 가입 후 24시간 내 클릭 필수, 미인증 시 게시·후원 제한 |
| 비밀번호 정책 | 최소 8자, 대소문자+숫자+특수문자 중 3종 이상 (NIST SP 800-63B) |
| Google 중복 이메일 | 409 + setup_password URL 반환 (통합 안내) |
| bcrypt cost | 12 (기존 admin과 동일) |
| 로그인 실패 잠금 | 5회 실패 → 15분 잠금 (admin 패턴 동일) |

### AC
1. `POST /auth/register` → 신규 사용자 생성 + 인증 메일 발송 + access/refresh 토큰 반환
2. `POST /auth/login/email` → 비밀번호 검증 + 잠금 정책 + 토큰 반환
3. `POST /auth/email/verify` → 토큰 검증 후 `email_verified=true`
4. `POST /auth/email/verify/resend` → 5분 cooldown 재발송
5. 미인증 사용자: 게시·후원 API → 403 `EMAIL_NOT_VERIFIED`
6. 기존 Google OAuth 흐름 무영향
7. audit_log 기록 (user.register, user.login, user.email_verified)
8. i18n 5 locale (ko/en/ja/zh/es) 지원

## 2. Database Schema (alembic 0085)

### 추가 컬럼 (users 테이블)

| 컬럼 | 타입 | DEFAULT | 설명 |
|------|------|---------|------|
| `email_verified` | BOOLEAN | FALSE | 이메일 인증 완료 |
| `email_verification_token` | VARCHAR(64) | NULL | 인증 토큰 (urlsafe) |
| `email_verification_sent_at` | TIMESTAMPTZ | NULL | 발송 시각 (5분 cooldown) |
| `email_verification_expires_at` | TIMESTAMPTZ | NULL | 만료 시각 (24h) |
| `failed_login_locked_until` | TIMESTAMPTZ | NULL | 일반 사용자 잠금 해제 시각 |

**기존 컬럼 재활용** (이미 users 테이블에 존재):
- `password_hash VARCHAR(255) NULL` — bcrypt cost=12, admin과 공유
- `failed_login_count INTEGER DEFAULT 0` — admin과 공유, 의미 맥락은 동일

**신규 컬럼 설명**:
- `failed_login_locked_until`: admin의 `locked_until`과 분리하여 일반 사용자 잠금 상태 관리
- `email_verified`: False인 경우 게시물 작성/후원 결제 차단
- 5분 cooldown: `email_verification_sent_at`으로 계산

### Model 변경 (user.py)

```python
# D-3 이메일 인증 필드 (alembic 0085)
email_verified: Mapped[bool] = mapped_column(Boolean, default=False)
email_verification_token: Mapped[str | None] = mapped_column(String(64), nullable=True)
email_verification_sent_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
email_verification_expires_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
failed_login_locked_until: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
```

## 3. Backend Endpoints

### 3.1 POST /auth/register

**Request**:
```json
{
  "email": "user@example.com",
  "password": "Passw0rd!",
  "display_name": "작가이름"
}
```

**비즈니스 로직**:
1. 이메일 소문자 정규화
2. `validate_password()` 호출 (8자+, 3종 이상)
3. Google 계정 중복 확인 → 409 + `setup_password_url`
4. bcrypt hash 생성 (cost=12)
5. User 생성 (`email_verified=False`, `sns_provider=None`)
6. 인증 토큰 생성 + DB 저장 + 이메일 발송 (graceful)
7. 토큰 발급 + audit_log(`user.register`)

**Response (201)**:
```json
{
  "data": {
    "tokens": { "access_token": "...", "refresh_token": "..." },
    "user": { ... },
    "email_verification_sent": true
  }
}
```

**Error 케이스**:
- 이메일 중복 (Google): 409 `GOOGLE_ACCOUNT_EXISTS` + `setup_password_url`
- 이메일 중복 (일반): 409 `EMAIL_ALREADY_EXISTS`
- 비밀번호 미충족: 422 `PASSWORD_TOO_SHORT` / `PASSWORD_WEAK`

### 3.2 POST /auth/login/email

**Request**: `{ "email": "...", "password": "..." }`

**비즈니스 로직**:
1. 사용자 조회 (email, role != admin)
2. `failed_login_locked_until` 잠금 확인 → 423
3. `verify_password()` — 실패 시 `failed_login_count++`, 5회 이상 → `failed_login_locked_until` 15분 후
4. 성공 시 카운터 초기화
5. 토큰 발급 + audit_log(`user.login`)

**Response (200)**:
```json
{
  "data": {
    "tokens": { "access_token": "...", "refresh_token": "..." },
    "user": { ... },
    "email_verified": false
  }
}
```

### 3.3 POST /auth/email/verify

**Request**: `{ "token": "..." }`

**비즈니스 로직**:
1. `email_verification_token` 조회
2. `email_verification_expires_at` 만료 확인 → 410 GONE
3. `email_verified=True`, 토큰 필드 NULL 처리
4. audit_log(`user.email_verified`)

### 3.4 POST /auth/email/verify/resend

**인증 필요** (Bearer 토큰)

**비즈니스 로직**:
1. 이미 인증됨 → 400 `ALREADY_VERIFIED`
2. 5분 cooldown 확인 → 429 `RESEND_TOO_SOON`
3. 토큰 재생성 + 이메일 재발송

## 4. Frontend

### LoginModal.tsx 확장

```
[탭] 로그인 | 회원가입
---
이메일 입력
비밀번호 입력 + 강도 표시
[로그인 버튼] / [회원가입 버튼]
─── 또는 ───
[Google로 계속하기]
비밀번호 찾기 (비활성 — Phase 12)
```

**상태 관리**:
- `mode: 'login' | 'signup'`
- `passwordStrength: 0~4` (실시간 계산)
- 성공 후 `email_verified: false`이면 인증 안내 배너 표시

### api.ts 추가 함수

```typescript
registerWithPassword(body: RegisterBody): Promise<RegisterResult>
loginWithEmailPassword(body: LoginBody): Promise<LoginResult>  
verifyEmail(token: string): Promise<{verified: boolean}>
resendVerificationEmail(): Promise<{sent: boolean}>
```

### /auth/verify/page.tsx (신규)

- URL: `/auth/verify?token=xxx`
- 마운트 시 `verifyEmail(token)` 호출
- 성공 → "인증 완료" → 홈으로 리다이렉트
- 실패/만료 → 에러 메시지 + 재발송 링크

## 5. 보안 검증

### 비밀번호 정책 (NIST SP 800-63B)
- 최소 8자
- 대소문자 / 숫자 / 특수문자 중 3종 이상
- bcrypt 72바이트 한도 명시적 reject (기존 security.py 패턴)

### 잠금 정책
- `failed_login_count` >= 5 → `failed_login_locked_until` = now + 15분
- 성공 로그인 → 카운터 초기화
- admin의 `locked_until`과 별도 컬럼으로 충돌 없음

### 이메일 인증 토큰
- `secrets.token_urlsafe(32)` = 43자 (256비트 엔트로피)
- DB 평문 저장 (단일 사용 후 NULL 처리)
- 24시간 만료

### rate limit
- `/auth/register` → `auth_login` 키 (IP 기준 10/min)
- `/auth/login/email` → `auth_login` 키 동일 적용

## 6. Test Plan

### Unit Tests (`tests/unit/test_password_auth.py`)
1. `validate_password` — 8자 미만 → `PASSWORD_TOO_SHORT`
2. `validate_password` — 2종 조합 → `PASSWORD_WEAK`
3. `validate_password` — 3종 조합 → 통과
4. `validate_password` — 72바이트 초과 → `PASSWORD_TOO_LONG`
5. bcrypt hash 생성 및 verify 일치
6. bcrypt 다른 비밀번호 → verify 불일치
7. `generate_verification_token()` 길이 43자 확인
8. 토큰 expires_at = now + 24h 확인

### Integration Tests (`tests/integration/test_auth_email_password.py`)
1. `POST /auth/register` 정상 → 201 + tokens
2. 이메일 중복 (Google 계정) → 409 `GOOGLE_ACCOUNT_EXISTS`
3. 이메일 중복 (비밀번호 계정) → 409 `EMAIL_ALREADY_EXISTS`
4. 비밀번호 정책 미충족 → 422
5. `POST /auth/login/email` 정상 → 200 + tokens
6. 잘못된 비밀번호 → 401 `INVALID_CREDENTIALS`
7. 5회 실패 잠금 → 423 `ACCOUNT_LOCKED`
8. `POST /auth/email/verify` 유효 토큰 → 200 + `verified: true`
9. `POST /auth/email/verify` 만료 토큰 → 410 `VERIFICATION_TOKEN_EXPIRED`
10. 미인증 사용자 게시물 작성 시도 → 403 `EMAIL_NOT_VERIFIED`
