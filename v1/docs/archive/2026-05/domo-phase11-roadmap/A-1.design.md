# Phase 11 A-1 Design — Admin Featured Artist 검수 큐 UI

> **Summary**: Phase 10 K-4에서 구축한 주간 Featured Artist 자동 선정 시스템의 Admin 검수 큐
> 프론트엔드를 구현한다. 백엔드 API 4개(candidates/approve/publish/reject)는 이미 완성된 상태이며,
> 프론트엔드만 부재하여 운영자가 DB를 직접 조작해야 하는 상황을 해제한다.
> autopublish OFF (사용자 OQ 권장 default 수락), 거부 사유 필수.

## 1. 목표 & Acceptance Criteria

### 목표

| # | 목표 | 근거 |
|---|------|------|
| 1 | Admin 콘솔에서 주간 ML 후보 5명을 검수할 수 있는 카드 그리드 UI 구현 | 현재 DB 직접 조작 의존 상태 해제 |
| 2 | approve → publish 2단계 워크플로 명시적 표현 | autopublish OFF 정책 준수 (OQ-6) |
| 3 | 거부 사유 입력 모달 (10~500자, 필수) 구현 | 단순 거부 차단, 모델 학습 negative signal 확보 |
| 4 | 과거 8주 결과 드롭다운으로 이력 열람 가능 | 운영 이력 추적 |
| 5 | composite_score 4개 가중치 분해 시각화 | admin이 선정 근거 투명하게 확인 |
| 6 | AdminShell 사이드바에 "Curation" 그룹 신규 추가 | 향후 A-2(AI 컬렉션 검수)와 함께 확장 |

### Acceptance Criteria (A-1 종결 조건)

- [ ] `/admin/featured-artist-queue` 접근 시 5개 후보 카드 그리드 표시 확인
- [ ] composite_score 4개 가중치(engagement/rank/diversity/new_artist_bonus) 시각화 표시 확인
- [ ] Approve 클릭 → `POST .../approve` 호출 → 카드 border 초록 변경 + "승인됨" 배지 확인
- [ ] Publish 클릭 (approved 상태에서만 활성) → `POST .../publish` 호출 → "발행됨" 배지 + 액션 disabled 확인
- [ ] Reject 클릭 → 사유 모달 → 10자 미만 제출 불가 → 거부 확정 → "거부됨" 카드 확인
- [ ] 주간 드롭다운 (최근 8주) → 해당 주 데이터 재조회 확인
- [ ] AdminShell 사이드바 "Curation" 그룹 + "Featured Artist 검수" 링크 확인
- [ ] admin 권한 없는 사용자 → 페이지 접근 시 `/` 리다이렉트 확인
- [ ] 401 응답 → 자동 로그아웃 + `/login` 리다이렉트 확인
- [ ] tsc 0 errors, lint 0 errors

### KPIs

| 지표 | 목표 | 측정 방법 |
|------|:----:|---------|
| admin 수락률 (자동 선정 정확도) | ≥ 70% | DB: `status='approved'` / `status IN ('approved','rejected')` |
| 검수 평균 시간 | ≤ 3분 | `AVG(reviewed_at - created_at)` WHERE status IN ('approved','rejected') |
| autopublish OFF 유지 | 100% | approve와 publish 별도 액션 구조 유지 |
| 운영 후 4주 수락률 위젯 표시 | 4주 후 | 통계 위젯 조건부 표시 |

## 2. Architecture

### 데이터 플로우

```
[K-4 Cron — 매주 월요일 09:00 UTC]
  select_candidates_for_week() → composite_score 계산
  INSERT INTO featured_artist_candidates (status='pending')
       ↓
[Admin 콘솔 — /admin/featured-artist-queue]
  GET /api/admin/featured-artist/candidates?week_start={date}
  → 5개 후보 카드 그리드 렌더링
       ↓ admin 액션
  ├── POST .../approve → status='approved' → 카드 border 초록
  ├── POST .../publish → status='published' → featured_artists INSERT → 홈 노출
  └── POST .../reject + {reason} → status='rejected' → 카드 회색 처리
```

### 권한 구조

- 페이지 진입: `fetchMe()` → role !== "admin" → `router.replace("/")`
- 모든 API 호출: `require_admin_with_2fa` (백엔드에서 강제, 401/403 처리)
- 401 응답: `apiFetch` 내 자동 refresh 시도 → 실패 시 `tokenStore.clear()` + `/login` 리다이렉트

### 캐시 전략

- 서버 캐시 불필요 (5명 데이터, 소량)
- 클라이언트: 액션 수행 후 즉시 로컬 state 업데이트 (re-fetch 최소화)
- 주간 드롭다운 변경 시에만 API 재호출

### lib/api.ts 추가 함수

```typescript
// ─── Featured Artist Queue (Phase 11 A-1) ────────────────────────────────

export async function fetchFeaturedArtistCandidates(
  weekStart?: string,
  status?: CandidateStatus
): Promise<FeaturedArtistCandidatesResponse> {
  const qs = new URLSearchParams();
  if (weekStart) qs.set("week_start", weekStart);
  if (status) qs.set("status", status);
  return apiFetch<FeaturedArtistCandidatesResponse>(
    `/admin/featured-artist/candidates?${qs}`
  );
}

export async function approveCandidate(
  id: string
): Promise<CandidateApproveResponse> {
  return apiFetch<CandidateApproveResponse>(
    `/admin/featured-artist/candidates/${id}/approve`,
    { method: "POST", body: JSON.stringify({}) }
  );
}

export async function publishCandidate(
  id: string,
  notes?: string
): Promise<CandidatePublishResponse> {
  return apiFetch<CandidatePublishResponse>(
    `/admin/featured-artist/candidates/${id}/publish`,
    { method: "POST", body: JSON.stringify({ notes: notes ?? "" }) }
  );
}

export async function rejectCandidate(
  id: string,
  reason: string
): Promise<CandidateRejectResponse> {
  return apiFetch<CandidateRejectResponse>(
    `/admin/featured-artist/candidates/${id}/reject`,
    { method: "POST", body: JSON.stringify({ reason }) }
  );
}
```

### `lib/hooks/useFeaturedArtistQueue.ts`

```typescript
import { useState, useCallback } from "react";
import {
  fetchFeaturedArtistCandidates,
  approveCandidate,
  publishCandidate,
  rejectCandidate,
  FeaturedArtistCandidate,
  FeaturedArtistCandidatesResponse,
} from "@/lib/api";

type ActionLoading = { id: string; action: "approve" | "publish" | "reject" } | null;

export function useFeaturedArtistQueue(weekStart: string) {
  const [data, setData] = useState<FeaturedArtistCandidatesResponse | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [actionLoading, setActionLoading] = useState<ActionLoading>(null);

  const load = useCallback(async () => {
    setLoading(true);
    setError(null);
    try {
      const res = await fetchFeaturedArtistCandidates(weekStart);
      setData(res);
    } catch (e: any) {
      setError(e?.message ?? "데이터를 불러오지 못했습니다.");
    } finally {
      setLoading(false);
    }
  }, [weekStart]);

  // 로컬 state에서 특정 후보의 status를 즉시 업데이트 (낙관적 업데이트)
  const updateCandidateStatus = useCallback(
    (id: string, updates: Partial<FeaturedArtistCandidate>) => {
      setData((prev) => {
        if (!prev) return prev;
        return {
          ...prev,
          candidates: prev.candidates.map((c) =>
            c.id === id ? { ...c, ...updates } : c
          ),
        };
      });
    },
    []
  );

  const approve = useCallback(
    async (id: string) => {
      setActionLoading({ id, action: "approve" });
      try {
        const res = await approveCandidate(id);
        updateCandidateStatus(id, {
          status: res.status,
          reviewed_at: res.reviewed_at,
        });
      } catch (e: any) {
        setError(e?.message ?? "승인에 실패했습니다.");
      } finally {
        setActionLoading(null);
      }
    },
    [updateCandidateStatus]
  );

  const publish = useCallback(
    async (id: string, notes?: string) => {
      setActionLoading({ id, action: "publish" });
      try {
        const res = await publishCandidate(id, notes);
        updateCandidateStatus(id, {
          status: res.status,
          published_at: res.published_at,
        });
      } catch (e: any) {
        setError(e?.message ?? "발행에 실패했습니다.");
      } finally {
        setActionLoading(null);
      }
    },
    [updateCandidateStatus]
  );

  const reject = useCallback(
    async (id: string, reason: string) => {
      setActionLoading({ id, action: "reject" });
      try {
        const res = await rejectCandidate(id, reason);
        updateCandidateStatus(id, {
          status: res.status,
          reviewed_at: res.reviewed_at,
          reasoning: {
            ...(data?.candidates.find((c) => c.id === id)?.reasoning ?? {
              engagement: 0,
              rank: 0,
              diversity: 0,
              new_artist_bonus: 0,
              sponsor_count: 0,
              follower_count: 0,
              region: null,
              genre: null,
            }),
            reject_reason: reason,
          },
        });
      } catch (e: any) {
        setError(e?.message ?? "거부에 실패했습니다.");
      } finally {
        setActionLoading(null);
      }
    },
    [updateCandidateStatus, data]
  );

  return { data, loading, error, load, approve, publish, reject, actionLoading };
}
```
