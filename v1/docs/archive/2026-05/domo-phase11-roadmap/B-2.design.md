# Phase 11 B-2 Design — Admin Diversity Config UI

> **Summary**: Phase 10 K-2에서 구현된 Diversity Reranking 백엔드(`diversity_configs` 테이블 + GET/PATCH API)에
> 대응하는 Admin 튜닝 페이지를 구현한다. 운영자가 `/admin/diversity-config`에서 `feed_default` 설정의
> 4개 파라미터를 슬라이더로 직접 조정하고 저장하면 Redis 캐시 만료(5분 이내) 후 피드 v2에 자동 적용된다.
> 변경 이력은 `updated_at` 기반으로 확인하고, 권장 기본값으로 재설정 버튼을 제공한다.
> B-1(A/B 실험 결과 페이지)과 병렬 개발하며 AdminShell "ML Operations" 그룹을 함께 신설한다.

---

## README 비전 연결

> "전 세계 아티스트들의 인덱스를 만들고 싶음" — Diversity Config 튜닝으로 신진작가 부스팅 강도와
> 장르·지역 다양성 제약을 운영 데이터에 맞게 월 1회 조율하여 언더-represented 지역 작가의 피드 노출 기회를 유지한다.

> "동유럽이든 남미든 동아시아든 — 꿈과 희망" — `region_min_diversity` 파라미터로 특정 지역 쏠림을
> 실시간 감지하고 운영자가 지역 quota를 직접 조정하여 글로벌 신진작가 발굴 기회를 보장한다.

### 1-1. 목표

| # | 목표 | 근거 |
|---|------|------|

### 2-2. 슬라이더 컴포넌트 명세

각 파라미터는 슬라이더(range input)와 숫자 입력(number input)이 양방향 sync된다.

| 파라미터 | 레이블 | 범위 | 권장 기본값 | 단위 | 설명 |
|---------|--------|:----:|:----------:|:----:|------|
| `emerging_artist_boost` | 신진작가 부스팅 배수 | 1.0 ~ 2.0 | 1.20 | 배수 (×) | 신진작가 게시물 스코어 배수. 1.0 = 비활성 |
| `genre_min_diversity` | 장르 최소 다양성 | 1 ~ 10 | 3 | 종 | 피드 top-K 내 최소 unique 장르 수 |
| `region_min_diversity` | 지역 최소 다양성 | 1 ~ 10 | 2 | 종 | 피드 top-K 내 최소 unique 지역 수 |
| `top_k_window` | Top-K 윈도우 크기 | 10 ~ 50 | 20 | 개 | 다양성 제약 적용 대상 피드 수 |

**슬라이더 단일 행 구조**:

```
[레이블]                              [현재값 숫자 입력] [단위]
|──────●──────────────────────| min: X   max: Y
[권장값: Z 라벨]
```

**step 설정**:
- `emerging_artist_boost`: step 0.05 (소수점 2자리)
- `genre_min_diversity`, `region_min_diversity`, `top_k_window`: step 1 (정수)

### 2-3. 변경 사항 미리보기

저장 버튼 위에 위치. 현재 슬라이더 값이 서버 값과 다를 때만 노출.

```
변경 사항 미리보기
┌───────────────────────────────────────────────┐
│ 신진작가 부스팅 배수   1.20  →  1.30          │
│ 장르 최소 다양성       3     →  4              │
└───────────────────────────────────────────────┘
```

- 변경된 파라미터만 행으로 표시 (변경 없으면 미리보기 영역 숨김)
- 이전 값: `text-text-muted`, 화살표 `→`, 새 값: `text-primary font-semibold`

### 2-4. "기본값으로 재설정" 버튼

- 위치: 저장 버튼 좌측 (outline 스타일)
- 클릭 시 확인 없이 즉시 슬라이더를 기본값으로 복원 + PATCH 호출
- 기본값: `emerging_artist_boost=1.20`, `genre_min_diversity=3`, `region_min_diversity=2`, `top_k_window=20`

### 3-4. `components/diversity/DiversityConfigForm.tsx`

**역할**: 4개 슬라이더 + 숫자 입력 + 변경 미리보기 + 저장/재설정 버튼.

**Props 인터페이스**:

```tsx
interface DiversityConfigFormProps {
  /** 서버에서 조회한 현재 feed_default 설정 */

  /** PATCH 호출 후 성공 시 부모가 캐시 무효화 */

```

**내부 상태**:
- `localValues: DiversityConfigPatch` — 슬라이더 조작 중간값
- `saving: boolean` — 저장 요청 중 flag

**DiversityConfigPatch 타입**:

```tsx
interface DiversityConfigPatch {
  emerging_artist_boost?: number;   // 1.0 ~ 2.0
  genre_min_diversity?: number;     // 1 ~ 10 (정수)
  region_min_diversity?: number;    // 1 ~ 10 (정수)
  top_k_window?: number;            // 10 ~ 50 (정수)
}
```

**변경 감지**: `localValues`와 `config`를 비교하여 diff가 있을 때만 미리보기 패널과 저장 버튼 활성화.

**저장 흐름**:
1. `saving = true`
2. `onSave(diff)` 호출 (diff = 변경된 필드만 포함한 partial object)
3. 성공 → 성공 토스트 + `localValues`를 새 값으로 초기화
4. 실패 → 에러 토스트 + `saving = false`

**재설정 흐름**:
1. `localValues` → defaults (`{ emerging_artist_boost: 1.20, genre_min_diversity: 3, region_min_diversity: 2, top_k_window: 20 }`)
2. 즉시 `onSave(defaults)` 호출

### 3-6. `lib/hooks/useDiversityConfig.ts`

TanStack Query를 사용하는 커스텀 훅.

```tsx
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import {
  adminListDiversityConfigs,
  adminPatchDiversityConfig,
} from "@/lib/api";

export function useDiversityConfig() {
  const queryClient = useQueryClient();

  const query = useQuery({
    queryKey: ["admin", "diversity-config"],
    queryFn: adminListDiversityConfigs,
    staleTime: 60_000, // 1분 — admin 페이지이므로 잦은 refetch 불필요
  });

  const mutation = useMutation({
    mutationFn: ({
      name,
      patch,
    }: {
      name: string;
      patch: DiversityConfigPatch;
    }) => adminPatchDiversityConfig(name, patch),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["admin", "diversity-config"] });
    },
  });

  const feedDefault = query.data?.find((c) => c.name === "feed_default") ?? null;

  return {
    configs: query.data ?? [],
    feedDefault,
    loading: query.isLoading,
    error: query.error,
    patch: mutation.mutateAsync,
    patching: mutation.isPending,
  };
}
```

### 3-7. `lib/api.ts` 확장 (2 함수 추가)

기존 `lib/api.ts` 파일 하단에 아래 두 함수를 추가한다.

**타입 정의**:

```tsx
/** GET /api/admin/diversity-config 응답 단일 항목 */
export interface DiversityConfigOut {
  id: string;
  name: string;
  emerging_artist_boost: number;
  genre_min_diversity: number;
  region_min_diversity: number;
  top_k_window: number;
  candidate_pool_size: number;
  status: "active" | "archived";
  created_at: string;
  updated_at: string;
}

/** PATCH /api/admin/diversity-config/{name} 요청 본문 */
export interface DiversityConfigPatch {
  emerging_artist_boost?: number;
  genre_min_diversity?: number;
  region_min_diversity?: number;
  top_k_window?: number;
}
```

**함수 2개**:

```tsx
/** 모든 diversity_configs 목록 조회 (admin 전용). */
export async function adminListDiversityConfigs(): Promise<DiversityConfigOut[]> {
  return apiFetch<DiversityConfigOut[]>("/admin/diversity-config");
}

/** 특정 config 부분 수정 (admin 전용). */
export async function adminPatchDiversityConfig(
  name: string,
  patch: DiversityConfigPatch
): Promise<DiversityConfigOut> {
  return apiFetch<DiversityConfigOut>(`/admin/diversity-config/${name}`, {
    method: "PATCH",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(patch),
  });
}
```

## 5. 슬라이더 + 입력 통합 상세

### 5-1. 양방향 sync 규칙

슬라이더와 숫자 입력은 동일한 `localValues[field]` 상태를 공유한다.

- 슬라이더 조작 → `onChange(parseFloat(e.target.value))` → `localValues` 업데이트 → 숫자 입력 갱신
- 숫자 입력 직접 수정 → `onBlur` 시 `clamp(value, min, max)` 적용 후 슬라이더 갱신
- `onChange` 중간에 범위 초과 입력이 들어오면 클라이언트에서 clamp하여 시각적 오류 방지
- 최종 PATCH 요청 시 서버에서도 422로 범위 검증 (이중 방어)

### 5-2. 유효 범위 표시

각 슬라이더 아래 min / 권장값 / max를 가로 배치:

```
|────────────────●─────────────────|
최솟값 1.0    권장값 1.20    최댓값 2.0
```

`accent-primary` CSS로 슬라이더 채움 색을 브랜드 컬러로 설정한다.

### 5-3. 저장 상태 피드백

| 상태 | 저장 버튼 | 미리보기 패널 |
|------|----------|------------|
| 변경 없음 | 비활성 (disabled) | 숨김 |
| 변경 있음 | 활성 (primary) | 표시 |
| 저장 중 | "저장 중..." + spinner | 유지 |
| 저장 성공 | 활성 복원 | 숨김 (값 초기화) |
| 저장 실패 | 활성 복원 | 유지 + 에러 토스트 |

## 6. 수동 테스트 시나리오

B-2 종결 전 반드시 확인할 수동 테스트 6가지:

### 시나리오 1: 현재 값 표시 확인

1. admin 계정으로 로그인 (2FA 완료)
2. `/admin/diversity-config` 진입
3. `feed_default` 카드의 4개 슬라이더가 DB 현재 값으로 초기화됨 확인
4. `updated_at` 타임스탬프가 페이지 헤더 subtitle에 표시됨 확인

### 시나리오 2: 슬라이더 변경 → 저장

1. `emerging_artist_boost` 슬라이더를 1.20 → 1.30으로 조작
2. 미리보기 패널에 "신진작가 부스팅 배수  1.20 → 1.30" 표시 확인
3. 저장 버튼 클릭
4. 성공 토스트 + `updated_at` 갱신 확인
5. 페이지 새로고침 후 슬라이더가 1.30으로 표시됨 확인 (서버 반영 검증)

### 시나리오 3: Redis 캐시 만료 후 피드 반영

1. 시나리오 2 완료 직후 `/api/feed?algo=v2` 호출 → 기존 캐시 응답 (부스팅 1.20 적용)
2. 5분 대기 후 동일 API 재호출 → 새 설정 (부스팅 1.30) 적용 확인
   - 신진작가 포스트 순위 변화 또는 서버 로그 `emerging_artist_boost=1.30` 확인으로 대체 가능

### 시나리오 4: 기본값 재설정

1. 모든 슬라이더를 임의 값으로 변경 (예: boost 1.50, genre 5, region 4, window 30)
2. "기본값으로 재설정" 버튼 클릭
3. 슬라이더가 즉시 1.20 / 3 / 2 / 20으로 복원됨 확인
4. PATCH 호출 성공 토스트 확인
5. DB 값 확인: `SELECT * FROM diversity_configs WHERE name='feed_default'`

### 시나리오 5: 유효 범위 외 입력 차단

1. `emerging_artist_boost` 숫자 입력에 `3.0` 직접 입력
2. 클라이언트: blur 시 2.0으로 clamp (시각적 오류 방지)
3. 슬라이더도 2.0으로 이동 확인
4. 만약 서버에 3.0이 도달하면 422 응답 + 에러 토스트 표시 확인 (이중 방어)

### 시나리오 6: 2FA 미완료 admin 리다이렉트

1. 2FA 미완료 admin 계정으로 로그인
2. `/admin/diversity-config` 진입
3. 페이지 렌더 없이 `/settings/totp-setup` 으로 리다이렉트 확인
