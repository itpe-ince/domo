## 4. testcontainers 통합 패턴

### 4.1 conftest.py 신규 fixture

`tests/conftest.py` 확장 (기존 파일에 추가):

```python
import os
import pytest
import pytest_asyncio
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession
from sqlalchemy.orm import sessionmaker

# testcontainers graceful skip (미설치 환경)
try:
    from testcontainers.postgres import PostgresContainer
    TESTCONTAINERS_AVAILABLE = True
except ImportError:
    TESTCONTAINERS_AVAILABLE = False

USE_TESTCONTAINERS = os.getenv("USE_TESTCONTAINERS", "false").lower() == "true"

# ── session scope: 컨테이너 한 번만 시작 ──────────────────────────────────────

@pytest.fixture(scope="session")
def pg_container():
    """PostgreSQL testcontainer (session scope, 한 번만 시작)."""
    if not USE_TESTCONTAINERS or not TESTCONTAINERS_AVAILABLE:
        pytest.skip("testcontainers 미설치 또는 USE_TESTCONTAINERS=false")
    with PostgresContainer("pgvector/pgvector:pg15") as pg:
        yield pg


@pytest.fixture(scope="session")
def real_db_engine(pg_container):
    """실제 PostgreSQL 엔진 + alembic upgrade head."""
    import subprocess
    db_url = pg_container.get_connection_url().replace(
        "postgresql://", "postgresql+asyncpg://"
    )
    # alembic upgrade head (변경 없음, 기존 migration 적용)
    sync_url = pg_container.get_connection_url()
    subprocess.run(
        ["alembic", "upgrade", "head"],
        env={**os.environ, "DATABASE_URL": sync_url},
        check=True,
        cwd="/path/to/backend",  # 실제 경로로 교체
    )
    engine = create_async_engine(db_url, echo=False)
    yield engine
    # 세션 종료 후 정리는 컨테이너 종료 시 자동 처리


@pytest_asyncio.fixture
async def real_db_session(real_db_engine):
    """function scope: 각 테스트마다 transaction rollback으로 격리."""
    async_session = sessionmaker(
        real_db_engine, class_=AsyncSession, expire_on_commit=False
    )
    async with async_session() as session:
        async with session.begin():
            yield session
            await session.rollback()  # 테스트 후 롤백 — 격리 보장
```

### 4.2 transaction rollback 격리 전략

```
컨테이너 시작 (session scope, 1회)
  └─ alembic upgrade head (1회)
       └─ 각 테스트: BEGIN → INSERT 픽스처 데이터 → 실행 → assert → ROLLBACK
```

- session scope: 컨테이너 시작 비용 (~20-30초) 1회 부담
- function scope rollback: 테스트 간 데이터 격리 보장
- alembic 변경 없음: 기존 migration만 적용

### 5.1 카테고리 1: audit_log_cleanup — freezegun + testcontainers (3건)

**대상 테스트**:
- `test_cleanup_deletes_old_rows`
- `test_cleanup_no_rows_no_commit`
- `test_cleanup_rowcount_none`

**현재 문제**: `AsyncMock` db에서 `rowcount` 검증이 실제 DELETE와 무관.

**refactor 방향**:

```python
from freezegun import freeze_time
from datetime import datetime, timedelta, timezone

@freeze_time("2026-05-08 12:00:00")
@pytest.mark.asyncio
async def test_cleanup_deletes_old_rows(real_db_session):
    """cutoff(365일) 이전 audit_log 3건 INSERT → cleanup 실행 → rowcount=3 검증."""
    from app.models.audit_log import AuditLog
    from app.services.audit_log_cleanup_jobs import cleanup_old_audit_logs

    # 1년 전 행 3건 INSERT (freezegun으로 현재 시각 = 2026-05-08)
    old_date = datetime(2025, 5, 7, 12, 0, 0, tzinfo=timezone.utc)  # 366일 전
    for _ in range(3):
        real_db_session.add(AuditLog(
            action="user.login", actor_id=None,
            target_type="user", created_at=old_date
        ))
    await real_db_session.flush()

    deleted = await cleanup_old_audit_logs(real_db_session)

    assert deleted == 3
    # rollback은 fixture가 처리

@freeze_time("2026-05-08 12:00:00")
@pytest.mark.asyncio
async def test_cleanup_no_rows_no_commit(real_db_session):
    """최근 행만 있을 때 cleanup → deleted=0, commit 불필요."""
    from app.services.audit_log_cleanup_jobs import cleanup_old_audit_logs

    # commit 호출 여부는 monkeypatch로 관찰 (실제 DB 세션이므로 rollback으로 격리)
    deleted = await cleanup_old_audit_logs(real_db_session)
    assert deleted == 0
```

- `freeze_time("2026-05-08")` → cutoff 계산의 기준일 고정
- 실제 PostgreSQL INSERT + DELETE로 `rowcount` 신뢰 확보

async def test_admin_create_user_audit(real_db_session, monkeypatch):

        display_name="New User",

async def test_personalized_feed_v1_returns_scored_data(real_db_session):

## 6. CI 영향

### GitHub Actions docker-in-docker 요건

```yaml
# .github/workflows/test.yml (기존 workflow 수정 시 참고)
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      # testcontainers가 자체 docker socket 사용 → services 선언 불필요
      # runner가 docker 지원하면 자동 동작
    steps:
      - name: Run tests with testcontainers
        env:
          USE_TESTCONTAINERS: "true"
        run: pytest tests/ -v
```

- `ubuntu-latest` runner: docker 내장 → testcontainers 동작 가능
- `macos-latest` runner: docker 미설치 → `USE_TESTCONTAINERS=false` (graceful skip)
- 로컬 개발: `USE_TESTCONTAINERS=true pytest tests/` 또는 기본 skip

### 실행 시간 예측

| 단계 | 소요 시간 |
|------|----------|
| PostgreSQL 컨테이너 시작 | 20-30초 (1회) |
| alembic upgrade head | 5-10초 |

## 7. testcontainers 미설치 시 Graceful Skip

```python
# tests/conftest.py 상단
import os

try:
    from testcontainers.postgres import PostgresContainer
    TESTCONTAINERS_AVAILABLE = True
except ImportError:
    TESTCONTAINERS_AVAILABLE = False

USE_TESTCONTAINERS = os.getenv("USE_TESTCONTAINERS", "false").lower() == "true"

@pytest.fixture(scope="session")
def pg_container():
    if not USE_TESTCONTAINERS:
        pytest.skip("USE_TESTCONTAINERS 환경변수가 설정되지 않음. 로컬 실행 시 필요.")
    if not TESTCONTAINERS_AVAILABLE:
        pytest.skip("testcontainers 미설치. pip install testcontainers[postgresql] 필요.")
    with PostgresContainer("pgvector/pgvector:pg15") as pg:
        yield pg
```

- `USE_TESTCONTAINERS=false` (기본값): testcontainers 의존 테스트 전체 skip → 기존 pipeline 영향 없음
- `USE_TESTCONTAINERS=true`: 컨테이너 시작, 실제 통합 테스트 실행
- testcontainers 미설치: ImportError graceful skip
