# Phase 12 C-3 Design — 키보드 단축키 확장

> **Summary**: Phase 11 D-1에서 확립한 `useGlobalHotkeys` hook 인프라 위에 GitHub/Slack
> 표준의 g-시퀀스 navigation 단축키 6개와 action 단축키 3개를 추가한다. 별도
> `useSequenceHotkeys` hook을 신규 작성해 시퀀스 패턴을 지원하고, `KeyboardShortcutsHelp`
> 모달을 4개 카테고리(navigation/feed/editor/general)로 재편한다.
> alembic 변경 없음. 5 locale i18n 완료 조건.

## 2. Sequence Hotkey 패턴 — `useSequenceHotkeys`

### 파일

`v1/frontend/src/lib/hooks/useSequenceHotkeys.ts`

### 타입 정의

```typescript
interface SequenceHotkey {
  /** 두 키 시퀀스. 예: ['g', 'h'] */
  sequence: [string, string];
  /** 두 번째 키 대기 타임아웃(ms). default 1000. Phase 12 C-3 권장: 1000ms */
  timeoutMs?: number;
  /** 시퀀스 매치 시 핸들러 */
  handler: (e: KeyboardEvent) => void;
  /**
   * false 로 설정하면 이 시퀀스를 등록하지 않는다. default: true
   */
  enabled?: boolean;
  /**
   * true(default)이면 input/textarea/select/contentEditable 포커스 시
   * 이 핸들러를 건너뛴다.
   */
  preventInInputs?: boolean;
}

export function useSequenceHotkeys(hotkeys: SequenceHotkey[]): void;
```

> 참고: plan 문서에는 300ms가 언급되어 있으나, 사용자 OQ에서 `timeoutMs` 기본값을 1000ms로
> 명시했다. hook 구현 시 `timeoutMs` 기본값은 1000ms로 적용한다. 300ms는 너무 짧아
> 타이핑 속도에 따라 실패율이 높을 수 있다.

### 구현 코드

```typescript
import { useEffect, useRef } from "react";

function shouldIgnoreSequenceHotkey(target: EventTarget | null): boolean {
  if (!(target instanceof HTMLElement)) return false;
  const tag = target.tagName.toLowerCase();
  if (tag === "input" || tag === "textarea" || tag === "select") return true;
  if (target.isContentEditable) return true;
  return false;
}

export function useSequenceHotkeys(hotkeys: SequenceHotkey[]): void {
  // 첫 번째 키 입력 상태를 ref로 관리 (리렌더 없이 유지)
  const lastKeyRef = useRef<{ key: string; at: number } | null>(null);
  // 타임아웃 클리어용 ref
  const timeoutIdRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(() => {
    function handleKeyDown(e: KeyboardEvent) {
      // meta/ctrl/alt 조합 키는 시퀀스에서 무시
      if (e.metaKey || e.ctrlKey || e.altKey) return;

      const now = Date.now();
      const last = lastKeyRef.current;

      // 활성화된 시퀀스 목록 필터링
      const activeHotkeys = hotkeys.filter(h => h.enabled !== false);

      // 입력 포커스 차단 여부 확인 (모든 활성 hotkey에 preventInInputs 확인)
      // preventInInputs !== false인 hotkey가 하나라도 있고 포커스가 input이면
      // 해당 키를 처리하지 않는다.
      const inInput = shouldIgnoreSequenceHotkey(e.target);

      // 첫 번째 키인지 확인
      const firstKeys = new Set(activeHotkeys.map(h => h.sequence[0]));

      if (last === null || (now - last.at) >= (hotkeys[0]?.timeoutMs ?? 1000)) {
        // 이전 시퀀스 상태 없음 또는 타임아웃 경과 → 첫 번째 키 처리
        if (timeoutIdRef.current) {
          clearTimeout(timeoutIdRef.current);
          timeoutIdRef.current = null;
        }
        lastKeyRef.current = null;

        if (firstKeys.has(e.key.toLowerCase())) {
          if (inInput) return; // 첫 번째 키도 입력 포커스 시 차단
          lastKeyRef.current = { key: e.key.toLowerCase(), at: now };

          // 타임아웃 설정: 대기 시간 경과 시 리셋
          const timeout = hotkeys.find(h =>
            h.sequence[0] === e.key.toLowerCase()
          )?.timeoutMs ?? 1000;

          timeoutIdRef.current = setTimeout(() => {
            lastKeyRef.current = null;
            timeoutIdRef.current = null;
          }, timeout);
          return;
        }
        // 첫 번째 키가 아니면 그냥 흘려보냄
        return;
      }

      // 두 번째 키 처리 (last !== null && 타임아웃 미경과)
      if (timeoutIdRef.current) {
        clearTimeout(timeoutIdRef.current);
        timeoutIdRef.current = null;
      }

      const matched = activeHotkeys.find(
        h =>
          h.sequence[0] === last.key &&
          h.sequence[1] === e.key.toLowerCase() &&
          !(h.preventInInputs !== false && inInput)
      );

      lastKeyRef.current = null;

      if (matched) {
        matched.handler(e);
      }
      // 매치 안 된 경우: 두 번째 키가 새 첫 번째 키가 될 수 있는지 확인
      else if (firstKeys.has(e.key.toLowerCase())) {
        if (!inInput) {
          lastKeyRef.current = { key: e.key.toLowerCase(), at: now };
          const timeout = hotkeys.find(h =>
            h.sequence[0] === e.key.toLowerCase()
          )?.timeoutMs ?? 1000;
          timeoutIdRef.current = setTimeout(() => {
            lastKeyRef.current = null;
            timeoutIdRef.current = null;
          }, timeout);
        }
      }
    }

    window.addEventListener("keydown", handleKeyDown);
    return () => {
      window.removeEventListener("keydown", handleKeyDown);
      if (timeoutIdRef.current) clearTimeout(timeoutIdRef.current);
    };
  }, [hotkeys]);
}
```

### D-1 `useGlobalHotkeys`와의 관계

`useSequenceHotkeys`는 `useGlobalHotkeys`와 **독립 hook**으로 분리한다. 두 hook은
동일한 `window` keydown 이벤트를 청취하지만 처리 대상이 다르다.

| 비교 항목 | `useGlobalHotkeys` (D-1) | `useSequenceHotkeys` (C-3 신규) |
|-----------|--------------------------|--------------------------------|
| 처리 패턴 | 단일 키 (j, k, ?, ⌘S) | 두 키 시퀀스 (g+h, g+f ...) |
| 상태 관리 | 없음 (stateless) | `lastKeyRef` + 타임아웃 |
| 수정자 키 | modifier 필드로 지원 | 지원 안 함 (meta/ctrl/alt 무시) |
| 호환성 | 변경 없음 유지 | 신규 hook — 기존 코드 영향 없음 |

두 hook은 AppShell에서 **병렬 호출**된다. 충돌 없음 — `g` 키는 `useGlobalHotkeys`에
등록된 단축키가 없으므로 `useSequenceHotkeys`만 처리한다.

## 3. AppShell 등록 코드

### 파일

`v1/frontend/src/components/AppShell.tsx` (수정)

### 추가 내용

```tsx
"use client";

import { useRouter, usePathname } from "next/navigation";
import { useCallback } from "react";
import { useGlobalHotkeys } from "@/lib/hooks/useGlobalHotkeys";
import { useSequenceHotkeys } from "@/lib/hooks/useSequenceHotkeys";

// AppShell 내부 — C-3 단축키 등록 블록
export function AppShell({ children }: { children: React.ReactNode }) {
  const router = useRouter();
  const pathname = usePathname();
  const { me } = useMe();
  const [helpOpen, setHelpOpen] = useState(false);  // D-1에서 이미 존재

  const isFeedPage = pathname === "/" || pathname === "/feed";

  // --- g-시퀀스 navigation (useSequenceHotkeys) ---
  useSequenceHotkeys([
    {
      sequence: ["g", "h"],
      handler: () => router.push("/"),
      enabled: !helpOpen,
    },
    {
      sequence: ["g", "f"],
      handler: () => router.push("/feed"),
      enabled: !helpOpen,
    },
    {
      sequence: ["g", "e"],
      handler: () => router.push("/explore"),
      enabled: !helpOpen,
    },
    {
      sequence: ["g", "m"],
      handler: () => router.push("/me/messages"),
      enabled: !helpOpen,
    },
    {
      sequence: ["g", "n"],
      handler: () => router.push("/notifications"),
      enabled: !helpOpen,
    },
    {
      sequence: ["g", "p"],
      handler: () => {
        if (me?.id) router.push(`/users/${me.id}`);
      },
      enabled: !helpOpen && !!me,
    },
  ]);

  // --- 단일 키 action 단축키 (useGlobalHotkeys 확장) ---
  // D-1에서 등록한 j/k/?에 n//(slash)/b 추가
  useGlobalHotkeys([
    // D-1 기존 단축키
    {
      key: "j",
      handler: () => navigateFeed("next"),
      enabled: isFeedPage && !helpOpen,
    },
    {
      key: "k",
      handler: () => navigateFeed("prev"),
      enabled: isFeedPage && !helpOpen,
    },
    {
      key: "?",
      handler: () => setHelpOpen(true),
      enabled: !helpOpen,
    },
    // C-3 신규 단축키
    {
      key: "n",
      handler: () => router.push("/posts/new"),
      enabled: !helpOpen,
      // preventInInputs: true (default) — 입력 중 비활성
    },
    {
      key: "/",
      handler: (e) => {
        e.preventDefault();
        focusSearchBar();
      },
      enabled: !helpOpen,
    },
    {
      key: "b",
      handler: () => toggleActivePostBookmark(),
      enabled: !helpOpen,
      // preventInInputs: true (default)
    },
  ]);

  // ... 나머지 AppShell 구현
}
```

### `focusSearchBar` 구현 전략

SearchBar가 헤더 또는 피드/탐색 페이지에 존재할 수 있으므로, `data-search-input` 속성으로
DOM 쿼리한다.

```tsx
const focusSearchBar = useCallback(() => {
  const searchInput = document.querySelector<HTMLElement>("[data-search-input]");
  if (searchInput) {
    searchInput.focus();
  }
}, []);
```

SearchBar 컴포넌트에서 `<input data-search-input ... />` 속성 추가가 필요하다.

### `toggleActivePostBookmark` 구현 전략

D-1의 j/k `getActiveIndex` 패턴을 그대로 준용한다.

```tsx
const toggleActivePostBookmark = useCallback(() => {
  const cards = Array.from(
    document.querySelectorAll<HTMLElement>("[data-feed-item]")
  );
  if (cards.length === 0) return;

  const activeIdx = getActiveIndex(cards);  // D-1 헬퍼 함수 재사용
  const activeCard = cards[activeIdx];

  // 각 FeedItem/PostCard에 data-post-id 속성 필요
  const postId = activeCard.dataset.postId;
  if (!postId) return;

  // 북마크 토글 버튼을 프로그래매틱하게 클릭 (이벤트 버블링 활용)
  const bookmarkBtn = activeCard.querySelector<HTMLElement>("[data-bookmark-btn]");
  if (bookmarkBtn) {
    bookmarkBtn.click();
  }
}, []);
```

`FeedItem` 또는 `PostCard` 컴포넌트의 북마크 버튼에 `data-bookmark-btn` 속성 추가가 필요하다.
버튼 클릭 방식을 사용하면 기존 북마크 로직(API 호출, 낙관적 업데이트)을 그대로 재활용한다.

## 5. `KeyboardShortcutsHelp` 카테고리 확장

### 4개 카테고리 와이어프레임

```
┌─ 키보드 단축키 ────────────────────────────┐
│                                  [×] 닫기 │
│                                           │
│ Navigation                                │
│  g h      홈                              │
│  g f      피드                            │
│  g e      탐색                            │
│  g m      메시지                          │
│  g n      알림                            │
│  g p      프로필                          │
│                                           │
│ Feed                                      │
│  j        다음 게시물                      │
│  k        이전 게시물                      │
│  b        북마크 토글                      │
│                                           │
│ Editor                                    │
│  ⌘S / Ctrl+S   임시저장                   │

│                                           │
│ General                                   │
│  /        검색 포커스                      │

│  Esc      모달 닫기                        │
└───────────────────────────────────────────┘
```

### g-시퀀스 키 표기

시퀀스 단축키는 두 `<Kbd>` 요소를 나란히 표시한다.

```tsx
<ShortcutRow
  keys={[
    <span key="g-h" className="inline-flex items-center gap-0.5">
      <Kbd>g</Kbd>
      <Kbd>h</Kbd>
    </span>,
  ]}
  description={t("keyboardShortcuts.action.gotoHome")}
/>
```

### 컴포넌트 구조 변경 요약

기존 3개 카테고리(feed/editor/general) → 4개 카테고리(navigation/feed/editor/general).

- `section aria-labelledby="shortcut-category-navigation"` 신규 추가 (최상단)
- feed 카테고리에 `b` (북마크 토글) 행 추가
- editor 카테고리에 `n` (새 포스트) 행 추가
- general 카테고리에 `/` (검색 포커스) 행 추가
- admin 카테고리: Phase 12 C-3에서는 구현 제외. `me?.role === "admin"` 시에만
  렌더하는 조건부 섹션으로 자리만 잡아두고 항목은 빈 상태 (Phase 13 범위).

## 8. D-1 호환성 주의 사항

### 변경하지 않는 것

- `useGlobalHotkeys` hook 시그니처 및 내부 로직 — 수정 없음
- `shouldIgnoreHotkey` 헬퍼 함수 — 수정 없음 (필요 시 `useSequenceHotkeys.ts`에 동일 함수 복사)
- `KeyboardShortcutsHelp` props 인터페이스 (`open`, `onClose`) — 수정 없음
- ⌘S 임시저장 단축키 (`posts/new/page.tsx`) — 수정 없음

### AppShell 수정 시 유의 사항

D-1에서 AppShell에 등록한 `useGlobalHotkeys` 호출이 이미 존재한다. C-3에서는 해당
배열에 `n`, `/`, `b` 세 항목을 **추가**한다. 기존 `j`, `k`, `?` 항목은 그대로 유지.

```tsx
// 기존 D-1 등록 (변경 없음)
useGlobalHotkeys([
  { key: "j", handler: () => navigateFeed("next"), enabled: isFeedPage && !helpOpen },
  { key: "k", handler: () => navigateFeed("prev"), enabled: isFeedPage && !helpOpen },
  { key: "?", handler: () => setHelpOpen(true), enabled: !helpOpen },
  // C-3 추가 (아래만 신규)
  { key: "n", handler: () => router.push("/posts/new"), enabled: !helpOpen },
  { key: "/", handler: (e) => { e.preventDefault(); focusSearchBar(); }, enabled: !helpOpen },
  { key: "b", handler: () => toggleActivePostBookmark(), enabled: !helpOpen },
]);
```

### `useGlobalHotkeys`의 modifier 없는 키 처리

D-1 구현에서 modifier 없는 단순 키는 meta/ctrl/alt 조합이 눌린 경우를 무시한다.
`/` 키(`e.key === "/"`)도 modifier 없는 단순 키이므로 동일 로직 적용. 단, `e.preventDefault()`를
handler 내부에서 호출해 브라우저 기본 검색 동작을 차단해야 한다 (Firefox 퀵파인드 등).

### 주의 사항

- `useSequenceHotkeys`는 `useGlobalHotkeys`와 동일한 `window` keydown 리스너를 각각 등록한다.
  이벤트 전파 순서는 등록 순서에 따르나, 두 hook은 독립적으로 처리하므로 충돌 없음.
- `g` 키가 `useSequenceHotkeys`의 첫 번째 키로 등록되면, `useGlobalHotkeys`는 `g`에 대해
  등록된 핸들러가 없으므로 `g` 단독 입력 시 아무 동작도 하지 않는다.
- `n` 키는 `useGlobalHotkeys` `preventInInputs: true` (default)이므로 textarea 등 입력 중에는
  자동 비활성. 별도 처리 불필요.
- `focusSearchBar`와 `toggleActivePostBookmark`는 AppShell에서 `useCallback`으로 메모이제이션해
  `useGlobalHotkeys` deps 안정성을 유지한다.
- FeedItem `data-feed-item` 속성은 D-1에서 이미 추가됨. `data-post-id`만 신규 추가.
