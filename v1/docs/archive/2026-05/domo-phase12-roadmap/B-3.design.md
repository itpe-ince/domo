# Phase 12 B-3 Design — /admin/payouts 정산 관리 UI

> **Summary**: Phase 5에서 `settlement_jobs.py` 정산 배치 백엔드와 기본 admin API를 완성했으나
> 운영자가 Admin 콘솔에서 KYC 검수 큐를 처리하고 정산 이력을 조회하는 UI가 없다.
> B-3은 `/admin/payouts` 신규 페이지(3개 섹션 + 탭 구조)와 6개 백엔드 endpoint를 추가한다.
> alembic 마이그레이션 없음 — 기존 `settlements`, `settlement_items`, `kyc_sessions` 테이블 활용.
> KYC 검수 우선순위 FIFO, auto-publish OFF(admin 명시 승인), Stripe Connect 기존 인프라 그대로.

## 2. Database 검증 (alembic 변경 없음)

### 2-1. 기존 테이블 현황

B-3은 alembic 마이그레이션 없이 기존 테이블을 활용한다.

#### settlements 테이블 (alembic ~0060, Phase 5)

```
settlements(
  id              UUID PRIMARY KEY,
  artist_id       UUID REFERENCES users(id),
  period_start    DATE NOT NULL,
  period_end      DATE NOT NULL,
  order_count     INTEGER DEFAULT 0,
  gross_amount    NUMERIC(12, 2),
  platform_fee    NUMERIC(12, 2),
  net_amount      NUMERIC(12, 2),
  currency        VARCHAR(3) DEFAULT 'KRW',
  status          VARCHAR(20) DEFAULT 'pending',  -- pending|approved|paid|failed
  approved_by     UUID REFERENCES users(id),
  approved_at     TIMESTAMPTZ,
  paid_at         TIMESTAMPTZ,
  payout_reference VARCHAR(200),
  created_at      TIMESTAMPTZ DEFAULT NOW()
)
```

#### settlement_items 테이블 (Phase 5)

```
settlement_items(
  settlement_id   UUID REFERENCES settlements(id) ON DELETE CASCADE,
  order_id        UUID REFERENCES orders(id),
  PRIMARY KEY (settlement_id, order_id)
)
```

#### kyc_sessions 테이블 (Phase 5 또는 이전)

```
kyc_sessions(
  id                  UUID PRIMARY KEY,
  user_id             UUID REFERENCES users(id),
  provider            VARCHAR(20),           -- mock|toss|stripe
  external_session_id VARCHAR(200),
  status              VARCHAR(20) DEFAULT 'pending',  -- pending|processing|verified|failed|expired
  result_data         JSONB,
  created_at          TIMESTAMPTZ DEFAULT NOW(),
  completed_at        TIMESTAMPTZ
)
```

#### users 테이블 관련 컬럼 (KYC 상태)

```
users.identity_verified_at   TIMESTAMPTZ  -- NULL = 미인증
users.identity_provider      VARCHAR(20)  -- mock|toss|stripe
users.stripe_customer_id     VARCHAR(200) -- Stripe Customer ID (후속 연동용)
```

### 2-2. 권장 인덱스 추가 (마이그레이션 없이 CONCURRENTLY)

기존 인덱스가 부족한 경우 서비스 중단 없이 추가 가능하다.

```sql
-- 정산 이력 필터 쿼리 최적화
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_settlements_status
  ON settlements(status);

CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_settlements_artist_created
  ON settlements(artist_id, created_at DESC);

CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_settlements_period_start
  ON settlements(period_start DESC);

-- KYC 검수 큐 쿼리 최적화
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_kyc_sessions_status_created
  ON kyc_sessions(status, created_at ASC);  -- FIFO 정렬

CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_kyc_sessions_user_id
  ON kyc_sessions(user_id);
```

> 위 인덱스는 별도 alembic 없이 운영팀이 DB 콘솔에서 직접 적용 가능하다.
> 쿼리 성능 이슈 발생 시 Phase 13에서 alembic으로 정식 등록.

## 3. Backend Endpoints (6개 신규)

### 3-1. 라우터 위치

```
v1/backend/app/api/admin_payouts.py  (신규)
```

기존 `settlements.py`의 admin 라우트(`/admin/list`, `/admin/generate`, `/admin/{id}/approve`, `/admin/{id}/pay`)는 변경하지 않는다. B-3은 별도 파일로 분리해 KYC + Stripe Connect 관련 endpoint를 추가한다.

### 3-2. GET /admin/kyc/pending

**목적**: KYC 검수 대기 큐 (FIFO — 신청 순)

**권한**: `require_admin_with_2fa`

```python
GET /admin/kyc/pending
Query params:
  - limit: int = 20 (max 100)
  - offset: int = 0

Response 200:
{
  "data": [
    {
      "kyc_session_id": "uuid",
      "user_id": "uuid",
      "user_email": "artist@example.com",
      "user_display_name": "홍길동",
      "provider": "mock|toss|stripe",
      "created_at": "2026-05-01T00:00:00Z",
      "identity_verified_at": null,
      "stripe_customer_id": null
    }
  ],
  "pagination": { "total": 42, "offset": 0, "limit": 20 }
}
```

**구현 로직**:
- `kyc_sessions.status = 'pending'` 필터
- `users.identity_verified_at IS NULL` 조건 (이미 인증된 사용자 제외)
- `created_at ASC` 정렬 (FIFO)
- JOIN users 테이블로 email, display_name, stripe_customer_id 포함
- audit_log: `action="admin.kyc.queue_viewed"` (조회 이벤트)

### 3-3. POST /admin/kyc/{user_id}/approve

**목적**: KYC 승인 → Stripe Connect onboarding 트리거

**권한**: `require_admin_with_2fa`

```python
POST /admin/kyc/{user_id}/approve
Body: {}  (사유 없음 — 승인은 단순 확인)

Response 200:
{
  "data": {
    "user_id": "uuid",
    "kyc_approved_at": "2026-05-08T12:00:00Z",
    "stripe_connect_onboarding_url": "https://connect.stripe.com/setup/...",  # or null (mock 시)
    "provider": "mock"
  }
}
```

**구현 로직**:
1. `kyc_sessions` 최신 pending 세션 조회 (user_id 기준)
2. 세션이 없거나 이미 verified → 400 `KYC_SESSION_NOT_FOUND` 또는 409 `ALREADY_APPROVED`
3. `kyc_sessions.status = 'verified'`, `completed_at = now()`
4. `users.identity_verified_at = now()`, `users.identity_provider = session.provider`
5. Stripe Connect onboarding 시작:
   - `PAYMENT_PROVIDER=stripe` 환경: `stripe.AccountLink.create()` 호출 → onboarding URL 반환
   - 미설정/mock 환경: `onboarding_url = None` (graceful)
6. Notification 생성: `type="kyc_approved"`, `"KYC 인증이 승인되었습니다"`
7. audit_log: `action="admin.kyc.approved"`, `target_type="user"`, `target_id=user_id`

**에러 처리**:
- 없는 user_id → 404
- 이미 identity_verified_at 있음 → 409 `ALREADY_APPROVED`
- Stripe API 실패 → 경고 로그 + onboarding_url=null 반환 (500 아님)

### 3-4. POST /admin/kyc/{user_id}/reject

**목적**: KYC 거부 + 사유 저장 + 재신청 안내 알림

**권한**: `require_admin_with_2fa`

```python
POST /admin/kyc/{user_id}/reject
Body:
{
  "reason": "신분증 사진 불명확 — 재촬영 후 재신청 바랍니다"  # required, 1~500자
}

Response 200:
{
  "data": {
    "user_id": "uuid",
    "kyc_rejected_at": "2026-05-08T12:00:00Z",
    "reason": "신분증 사진 불명확..."
  }
}
```

**구현 로직**:
1. `kyc_sessions` 최신 pending 세션 조회
2. `kyc_sessions.status = 'failed'`, `completed_at = now()`
3. `kyc_sessions.result_data = {"admin_reject_reason": reason, "rejected_by": admin.id}`
4. Notification 생성:
   - `type="kyc_rejected"`
   - `title="KYC 인증이 거부되었습니다"`
   - `body=f"사유: {reason}. 수정 후 재신청해 주세요."`
   - `link="/settings/identity"`
5. audit_log: `action="admin.kyc.rejected"`, `target_type="user"`, `target_id=user_id`, `after_data={"reason": reason}`

**에러 처리**:
- reason 빈 문자열 → 422 `REASON_REQUIRED`
- 없는 user_id → 404
- pending 세션 없음 → 409 `NO_PENDING_KYC`

### 3-5. GET /admin/settlements

**목적**: 월별 정산 이력 조회 (필터: month, artist_id, status)

**권한**: `require_admin_with_2fa`

```python
GET /admin/settlements
Query params:
  - month: str | None        # "2026-04" 형식 (YYYY-MM)
  - artist_id: UUID | None
  - status: str | None       # pending|approved|paid|failed
  - limit: int = 20 (max 100)
  - offset: int = 0

Response 200:
{
  "data": [
    {
      "id": "uuid",
      "artist_id": "uuid",
      "artist_name": "홍길동",
      "artist_email": "artist@example.com",
      "period_start": "2026-04-01",
      "period_end": "2026-04-30",
      "order_count": 3,
      "gross_amount": "150000.00",
      "platform_fee": "15000.00",
      "net_amount": "135000.00",
      "currency": "KRW",
      "status": "paid",
      "approved_at": "2026-05-01T09:00:00Z",
      "paid_at": "2026-05-02T11:00:00Z",
      "payout_reference": "MOCK_PAYOUT_abc12345",
      "created_at": "2026-05-01T00:00:00Z"
    }
  ],
  "pagination": { "total": 100, "offset": 0, "limit": 20 },
  "export_url": "/admin/settlements/export?month=2026-04&format=csv"
}
```

**구현 로직**:
- month 파라미터 → `period_start >= '2026-04-01' AND period_end <= '2026-04-30'` 변환
- artist_id, status 필터 순차 적용
- JOIN users 테이블 → artist_name, artist_email 포함
- `created_at DESC` 정렬
- audit_log: `action="admin.settlement.list_viewed"` (필터 조건 after_data에 기록)

**목적**: 정산 상세 조회 (settlement_items + Stripe transfer 정보)

**권한**: `require_admin_with_2fa`

```python
GET /admin/settlements/{id}

Response 200:
{
  "data": {
    "id": "uuid",
    "artist_id": "uuid",
    "artist_name": "홍길동",
    "period_start": "2026-04-01",
    "period_end": "2026-04-30",
    "order_count": 3,
    "gross_amount": "150000.00",
    "platform_fee": "15000.00",
    "net_amount": "135000.00",
    "currency": "KRW",
    "status": "paid",
    "approved_at": "2026-05-01T09:00:00Z",
    "paid_at": "2026-05-02T11:00:00Z",
    "payout_reference": "MOCK_PAYOUT_abc12345",
    "items": [
      {
        "order_id": "uuid",
        "amount": "50000.00",
        "platform_fee": "5000.00",
        "inspection_completed_at": "2026-04-15T10:00:00Z"

      "transfer_id": "tr_xxx",    # or null (mock 시)
```

4. audit_log: `action="admin.settlement.detail_viewed"`, `target_id=settlement_id`

### 3-7. GET /admin/stripe-connect/{artist_id}/status

**목적**: Stripe Connect 계정 상태 fetch (현재 시점)

**권한**: `require_admin_with_2fa`

```python
GET /admin/stripe-connect/{artist_id}/status

Response 200:
{
  "data": {
    "artist_id": "uuid",
    "artist_name": "홍길동",
    "stripe_customer_id": "cus_xxx",          # or null
    "stripe_connect_account_id": "acct_xxx",   # or null (별도 컬럼 필요 시 Phase 13)
    "charges_enabled": true,
    "payouts_enabled": true,
    "requirements": {
      "currently_due": [],
      "eventually_due": ["individual.address.line1"],
      "disabled_reason": null
    },
    "mock_mode": true   # PAYMENT_PROVIDER != stripe 시 true
  }
}
```

**구현 로직**:
1. users 조회 → 없으면 404
2. `PAYMENT_PROVIDER != stripe` 또는 `stripe_customer_id IS NULL`:
   - mock 응답 반환: `charges_enabled=false`, `payouts_enabled=false`, `mock_mode=true`
3. `PAYMENT_PROVIDER=stripe`:
   - `stripe.Account.retrieve(connect_account_id)` 호출
   - `charges_enabled`, `payouts_enabled`, `requirements` 추출
   - Stripe API 실패 → 경고 로그 + mock 응답 반환 (500 아님)
4. audit_log: `action="admin.stripe_connect.status_checked"`, `target_id=artist_id`

> **참고**: `stripe_connect_account_id` 컬럼이 users 테이블에 없는 경우
> KYC approve 시 생성한 Account ID를 `users.stripe_customer_id`에 임시 저장하거나
> Phase 13에서 `users.stripe_connect_account_id` 컬럼 alembic 추가 검토.
> B-3에서는 mock 반환으로 처리.

## 4. Frontend — /admin/payouts 페이지

### 4-1. 라우터 구조

```
v1/frontend/src/app/(admin)/payouts/
  page.tsx                     # 메인 탭 컨테이너
  kyc-queue/
    page.tsx                   # KYC 검수 큐 (탭 1)
  settlements/
    page.tsx                   # 정산 이력 (탭 2)
    [id]/
      page.tsx                 # 정산 상세
  connect-status/
    page.tsx                   # Stripe Connect 상태 (탭 3)
```

단일 `/admin/payouts` 페이지 + 탭 구조로 구현한다. URL은 탭 전환 시 `?tab=kyc-queue|settlements|connect-status`로 query string 반영.

### 4-2. KYC 검수 큐 탭

```
┌─────────────────────────────────────────────────────────────┐
│ KYC 검수 큐 (n건 대기)                          [새로고침]  │
├──────────┬──────────────┬──────────┬────────────┬───────────┤
│ 신청일   │ 작가명       │ 이메일   │ 제공자     │ 액션      │
├──────────┼──────────────┼──────────┼────────────┼───────────┤
│ 05-01    │ 홍길동       │ artist@  │ mock       │ [승인][거부]│
│ 05-02    │ 김예술       │ kim@     │ toss       │ [승인][거부]│
└──────────┴──────────────┴──────────┴────────────┴───────────┘
```

- **승인 버튼**: confirm dialog ("이 작가의 KYC를 승인하시겠습니까?") → `POST /admin/kyc/{user_id}/approve`
- **거부 버튼**: 사유 입력 모달 (textarea, 최소 10자) → `POST /admin/kyc/{user_id}/reject`
- 처리 후 해당 행 큐에서 제거 (optimistic update + 응답 확인)
- 빈 큐: "대기 중인 KYC 신청이 없습니다" 상태 표시

### 4-3. 정산 이력 탭

```
┌─────────────────────────────────────────────────────────────┐
│ 정산 이력                    [필터] [CSV 내보내기]          │
│ 기간: [2026-04 ▼] 상태: [전체 ▼] 작가: [검색...]          │
├──────────┬──────────┬────────────┬──────────┬──────────────┤
│ 기간     │ 작가     │ 정산액(원) │ 상태     │ 승인일       │
```

```python
# stripe_real.py에 메서드 추가 (또는 별도 stripe_connect.py 신규)

async def get_or_create_connect_account(self, user_id: str, email: str) -> str:
    """Stripe Connect Express 계정 생성 (KYC approve 시 호출)."""
    def _create():
        account = self._stripe.Account.create(
            type="express",
            email=email,
            metadata={"user_id": user_id},
        )
        return account.id
    return await asyncio.to_thread(_create)

async def create_account_link(self, account_id: str, refresh_url: str, return_url: str) -> str:
    """Stripe Connect onboarding URL 생성."""
    def _create():
        link = self._stripe.AccountLink.create(
            account=account_id,
            refresh_url=refresh_url,
            return_url=return_url,
            type="account_onboarding",
        )
        return link.url
    return await asyncio.to_thread(_create)

async def get_connect_account_status(self, account_id: str) -> dict:
    """charges_enabled, payouts_enabled, requirements 조회."""
    def _retrieve():
        acct = self._stripe.Account.retrieve(account_id)
        return {
            "charges_enabled": acct.charges_enabled,
            "payouts_enabled": acct.payouts_enabled,
            "requirements": {
                "currently_due": list(acct.requirements.currently_due or []),
                "eventually_due": list(acct.requirements.eventually_due or []),
                "disabled_reason": acct.requirements.disabled_reason,
            },
        }
    return await asyncio.to_thread(_retrieve)
```

### 6-2. Graceful Fallback 패턴

모든 Stripe API 호출은 `try/except`로 감싸고 실패 시 mock 응답을 반환한다.

```python
async def _fetch_stripe_connect_status(artist_id: str, stripe_account_id: str | None) -> dict:
    if not stripe_account_id or get_settings().payment_provider != "stripe":
        return {
            "charges_enabled": False,
            "payouts_enabled": False,
            "requirements": {"currently_due": [], "eventually_due": [], "disabled_reason": None},
            "mock_mode": True,
        }
    try:
        provider = StripeProvider()
        status = await provider.get_connect_account_status(stripe_account_id)
        status["mock_mode"] = False
        return status
    except Exception as exc:
        log.warning("Stripe Connect status fetch failed for %s: %s", artist_id, exc)
        return {
            "charges_enabled": False,
            "payouts_enabled": False,
            "requirements": {"currently_due": [], "eventually_due": [], "disabled_reason": "fetch_failed"},
            "mock_mode": True,
        }
```
