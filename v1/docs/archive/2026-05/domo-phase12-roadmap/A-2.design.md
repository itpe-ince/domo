# Phase 12 A-2 Design — ML A/B 실험 제어 API (PATCH endpoint + 프론트 활성화)

> **Summary**: Phase 11 B-1에서 Admin 콘솔 `/admin/experiments` 조회 UI를 완성했으나
> 실험 일시정지/종료 PATCH endpoint를 미구현한 채 disabled tooltip으로 처리됐다.
> A-2는 백엔드 `PATCH /admin/experiments/{name}` endpoint를 추가하고,
> 프론트엔드 버튼을 활성화한다. alembic 마이그레이션 없음
> (기존 `ml_experiments` 테이블 + VARCHAR status 컬럼 그대로 활용).

## 2. 상태 전이 매트릭스

### 허용/차단 전이표

| 현재 상태 → 새 상태 | 허용 | 동작 상세 |
|-------------------|:----:|----------|
| draft → running | ✅ | `started_at` = now(UTC) 자동 갱신, PostHog flag 활성화 |
| draft → paused | ❌ | 400 `INVALID_TRANSITION` (시작 전 일시정지 불가) |
| draft → completed | ❌ | 400 `INVALID_TRANSITION` (시작 전 종료 불가) |
| running → paused | ✅ | 새 assignments 중단, 기존 사용자 variant 유지, PostHog flag 비활성 |
| running → completed | ✅ | `ended_at` = now(UTC) 자동 갱신, PostHog flag 영구 비활성 |
| running → draft | ❌ | 400 `INVALID_TRANSITION` (역행 불가) |
| paused → running | ✅ | 새 assignments 재개, PostHog flag 재활성화 |
| paused → completed | ✅ | `ended_at` = now(UTC) 자동 갱신, PostHog flag 영구 비활성 |
| paused → draft | ❌ | 400 `INVALID_TRANSITION` (역행 불가) |
| completed → * | ❌ | 400 `IMMUTABLE` (완료된 실험은 영구 보존, 모든 상태 변경 차단) |

### 유효 전이 다이어그램

```
draft ──────────────→ running ──────────────→ completed
                         ↕                        ║
                       paused ──────────────→ completed
                         ↑
                       running (재개)
```

- `completed`는 단방향 종착 상태 (재개/역행 모두 차단)
- `draft` → `draft`는 상태 변경 없음 (메타데이터 수정만 허용)

## 3. PATCH endpoint 스키마

### 3-1. Request

**URL**: `PATCH /admin/experiments/{name}`

**권한**: `require_admin_with_2fa` (Phase 12 plan OQ 결정 — 다른 admin endpoints와 동일)

**Path parameter**:

| 파라미터 | 타입 | 설명 |
|---------|------|------|
| `name` | string | 실험 고유 이름 (ml_experiments.name UNIQUE) |

**Request Body** (`ExperimentPatchRequest`):

```python
class ExperimentPatchRequest(BaseModel):
    status: Literal["draft", "running", "paused", "completed"] | None = None
    variant_distribution: dict[str, float] | None = None  # running 상태에서만 변경 가능
    target_metric: str | None = Field(None, max_length=50)
    hypothesis: str | None = None
    ended_at: datetime | None = None  # status=completed 시 자동 갱신 (요청값 무시)
```

**검증 규칙**:

1. `status`가 None이 아닌 경우 → 상태 전이 매트릭스 검사
2. `variant_distribution`이 제공된 경우:
   - 합계 검증: `sum(values) ∈ [0.99, 1.01]` (±0.01 허용)
   - 기존 variant 키 삭제 차단: 해당 variant에 assignment가 1건 이상이면 400 `ASSIGNMENTS_EXIST`
   - 새 variant 키 추가: 허용
3. `ended_at` 필드는 요청 body에서 무시 — status=completed 시 서버에서 자동 설정

### 3-2. Response

**성공** (`200 OK`):

```json
{
  "data": {
    "id": "uuid",
    "name": "feed_v2_rollout",
    "status": "paused",
    "variant_distribution": {"v1": 0.5, "v2": 0.5},
    "started_at": "2026-05-01T00:00:00Z",
    "ended_at": null,
    "target_metric": "feed_ctr",
    "hypothesis": "ML 피드가 CTR 15% 향상",
    "assignment_counts": {"v1": 1234, "v2": 1198},
    "created_at": "2026-05-01T00:00:00Z",
    "updated_at": "2026-05-08T10:00:00Z"
  }
}
```

**에러**:

| HTTP | 에러 코드 | 조건 |
|------|-----------|------|
| 404 | `NOT_FOUND` | 실험 이름 미존재 |
| 400 | `IMMUTABLE` | completed → 어떤 상태로든 변경 시도 |
| 400 | `INVALID_TRANSITION` | 허용되지 않은 상태 전이 (역행, draft→paused 등) |
| 400 | `ASSIGNMENTS_EXIST` | 기존 assignment가 있는 variant 키 삭제 시도 |
| 422 | (Pydantic) | variant_distribution 합 != 1.0 (±0.01 초과) |
| 403 | `FORBIDDEN` | non-admin 또는 2FA 미완료 |

### 3-3. 구현 코드 (`app/api/admin_experiments.py` 확장)

```python
# ── PATCH /admin/experiments/{name} ──────────────────────────────────────────

# 허용 전이 테이블
_ALLOWED_TRANSITIONS: dict[str, set[str]] = {
    "draft":     {"running"},
    "running":   {"paused", "completed"},
    "paused":    {"running", "completed"},
    "completed": set(),  # 종착 상태 — 모든 변경 차단
}


class ExperimentPatchRequest(BaseModel):
    """실험 상태 변경 + 메타데이터 수정 요청 body."""

    status: Literal["draft", "running", "paused", "completed"] | None = None
    variant_distribution: dict[str, float] | None = None
    target_metric: str | None = Field(None, max_length=50)
    hypothesis: str | None = None
    ended_at: datetime | None = None  # 무시됨 — 서버 자동 설정


@router.patch("/experiments/{name}")
async def patch_experiment(
    name: str,
    body: ExperimentPatchRequest,
    request: Request,
    admin: User = Depends(require_admin_with_2fa),
    db: AsyncSession = Depends(get_db),
):
    """실험 상태 변경 (pause/complete/resume) + 메타데이터 수정.

    상태 전이 검증, completed → * 차단, variant 키 삭제 차단, audit_log 기록.
    """
    import json  # noqa: PLC0415

    # 1. 실험 조회
    exp_result = await db.execute(
        text("""
            SELECT id, name, status, variant_distribution,
                   started_at, ended_at, target_metric, hypothesis,
                   created_at, updated_at
            FROM ml_experiments
            WHERE name = :name
            LIMIT 1
        """),
        {"name": name},
    )
    exp_row = exp_result.fetchone()
    if exp_row is None:
        raise ApiError("NOT_FOUND", f"Experiment '{name}' not found", http_status=404)

    current = _row_to_dict(exp_row)
    current_status = current["status"]

    # 2. 상태 전이 검증
    if body.status is not None and body.status != current_status:
        allowed = _ALLOWED_TRANSITIONS.get(current_status, set())
        if current_status == "completed":
            raise ApiError(
                "IMMUTABLE",
                "Completed experiments cannot be modified.",
                http_status=400,
            )
        if body.status not in allowed:
            raise ApiError(
                "INVALID_TRANSITION",
                f"Transition '{current_status}' → '{body.status}' is not allowed.",
                http_status=400,
            )

    # 3. variant_distribution 검증
    if body.variant_distribution is not None:
        total = sum(body.variant_distribution.values())
        if not (0.99 <= total <= 1.01):
            raise ApiError(
                "VALIDATION_ERROR",
                f"variant_distribution sum must be 1.0 (±0.01), got {total:.4f}",
                http_status=422,
            )
        # 기존 variant 키 삭제 차단
        existing_dist = current.get("variant_distribution") or {}
        if isinstance(existing_dist, str):
            existing_dist = json.loads(existing_dist)
        removed_keys = set(existing_dist.keys()) - set(body.variant_distribution.keys())
        if removed_keys:
            counts = await _get_assignment_counts(db, str(current["id"]))
            conflicting = [k for k in removed_keys if counts.get(k, 0) > 0]
            if conflicting:
                raise ApiError(
                    "ASSIGNMENTS_EXIST",
                    f"Cannot remove variant(s) {conflicting} with existing assignments.",
                    http_status=400,
                )

    # 4. 업데이트 필드 구성
    new_status = body.status or current_status
    now = datetime.now(timezone.utc)

    started_at = current.get("started_at")
    ended_at = current.get("ended_at")

    if body.status == "running" and current_status == "draft":
        started_at = now
    if body.status == "completed":
        ended_at = now

    dist_json = (
        json.dumps(body.variant_distribution)
        if body.variant_distribution is not None
        else None
    )

    # 5. UPDATE
    update_result = await db.execute(
        text("""
            UPDATE ml_experiments
            SET
                status               = :status,
                variant_distribution = COALESCE(:dist, variant_distribution),
                target_metric        = COALESCE(:metric, target_metric),
                hypothesis           = COALESCE(:hypothesis, hypothesis),
                started_at           = :started_at,
                ended_at             = :ended_at,
                updated_at           = now()
            WHERE name = :name
            RETURNING id, name, status, variant_distribution,
                      started_at, ended_at, target_metric, hypothesis,
                      created_at, updated_at
        """),
        {
            "status":     new_status,
            "dist":       dist_json,
            "metric":     body.target_metric,
            "hypothesis": body.hypothesis,
            "started_at": started_at,
            "ended_at":   ended_at,
            "name":       name,
        },
    )
    await db.commit()
    updated = _row_to_dict(update_result.fetchone())
    updated["id"] = str(updated["id"])
    updated["assignment_counts"] = await _get_assignment_counts(db, updated["id"])

    # 6. audit_log 기록
    await record_audit(
        db,
        actor=admin,
        action="admin.experiment_patch",
        target_type="experiment",
        metadata={
            "name":           name,
            "prev_status":    current_status,
            "new_status":     new_status,
            "fields_changed": [
                k for k in ("status", "variant_distribution", "target_metric", "hypothesis")
                if getattr(body, k) is not None
            ],
        },
        request=request,
    )

    # 7. PostHog flag 동기화 (비동기, 실패해도 응답 차단 안 함)
    try:
        await _sync_posthog_flag(name, new_status)
    except Exception as exc:  # noqa: BLE001
        log.warning("PostHog flag sync failed (non-critical): %s", exc)

    return {"data": updated}
```

## 4. PostHog Feature Flag 동기화 패턴

### 4-1. 동기화 규칙

| 상태 변경 | PostHog 동작 | 비고 |
|----------|:------------:|------|
| → running | feature flag 활성화 | 새 사용자 variant 할당 재개 |
| → paused | feature flag 비활성화 (일시) | 기존 assignments는 DB에 보존 |
| → completed | feature flag 영구 비활성화 | flag 삭제가 아닌 disabled 상태 유지 |

### 4-2. `_sync_posthog_flag` 구현

```python
async def _sync_posthog_flag(experiment_name: str, new_status: str) -> None:
    """PostHog Feature Flag를 실험 상태와 동기화.

    POSTHOG_API_KEY 미설정 시 graceful skip (K-8 패턴 유지).
    """
    api_key = os.getenv("POSTHOG_API_KEY")
    project_id = os.getenv("POSTHOG_PROJECT_ID")
    if not api_key or not project_id:
        log.debug("PostHog not configured — skipping flag sync for '%s'", experiment_name)
        return

    # flag key: experiment name을 그대로 사용 (K-8 기존 컨벤션)
    flag_key = experiment_name
    enabled = new_status == "running"

    import httpx  # noqa: PLC0415

    headers = {"Authorization": f"Bearer {api_key}"}
    url = f"{_POSTHOG_HOST}/api/projects/{project_id}/feature_flags/{flag_key}/"

    async with httpx.AsyncClient(timeout=5.0) as client:
        resp = await client.patch(
            url,
            headers=headers,
            json={"active": enabled},
        )
        if resp.status_code not in (200, 404):
            log.warning(
                "PostHog flag sync unexpected status %d for '%s'",
                resp.status_code,
                experiment_name,
            )
```

### 4-3. Graceful Fallback

PostHog API 호출 실패(타임아웃, 네트워크 오류, 404)는 `try/except`로 포착하고 `WARNING` 로그만 기록한다. 실험 상태 변경은 PostHog 동기화 성공 여부와 무관하게 DB에 이미 커밋된 상태이므로 응답 차단 없이 200 반환한다.

### 5-2. `lib/api.ts` 추가 함수

```typescript
// ── Experiment Patch ─────────────────────────────────────────────────────────

export interface ExperimentPatchPayload {
  status?: "draft" | "running" | "paused" | "completed";
  variant_distribution?: Record<string, number>;
  target_metric?: string;
  hypothesis?: string;
}

export async function patchExperiment(
  name: string,
  body: ExperimentPatchPayload,
): Promise<{ data: Experiment }> {
  return apiFetch(`/api/admin/experiments/${encodeURIComponent(name)}`, {
    method: "PATCH",
    body: JSON.stringify(body),
  });
}
```

### 5-3. `useExperiments.ts` — `usePatchExperiment` 추가

```typescript
export function usePatchExperiment() {
  const { refetch } = useExperiments();

  const [isPending, setIsPending] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const patch = async (name: string, body: ExperimentPatchPayload) => {
    setIsPending(true);
    setError(null);
    try {
      await patchExperiment(name, body);
      await refetch();  // 목록 갱신
    } catch (err) {
      setError(err instanceof Error ? err.message : "알 수 없는 오류");
    } finally {
      setIsPending(false);
    }
  };

  return { patch, isPending, error };
}
```

### 5-4. `ExperimentCard.tsx` — 버튼 활성화

기존 Phase 11 B-1에서 disabled tooltip 처리된 버튼을 상태별 가시성 규칙에 따라 활성화한다.

| paused | 재개 / 종료 | 활성 |
