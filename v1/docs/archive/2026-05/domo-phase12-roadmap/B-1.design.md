# Phase 12 B-1a Design — Admin Audit Log 조회 UI

> **Summary**: Phase 11 D-2에서 구축한 `audit_logs` PostgreSQL 테이블(alembic 0084)과
> `record_audit` 서비스를 토대로, Admin 콘솔에 `/admin/audit-logs` 조회 페이지를 신규 구현한다.
> actor / action / target_type / target_id / period 5종 필터 + cursor-based 페이지네이션(50건/페이지) +
> row 클릭 시 metadata JSONB 모달 표시. alembic 변경 없음(조회 전용).

---

## 1. 목표 & Acceptance Criteria

### 목표

| # | 목표 | 근거 |
|---|------|------|
| 1 | Admin 콘솔에 `/admin/audit-logs` 신규 페이지 제공 | 운영자가 Admin 액션 이력을 UI로 추적 가능하게 |
| 2 | `GET /admin/audit-logs` 백엔드 endpoint 구현 (cursor-based, 5종 필터) | 수동 DB 쿼리 없이 필터 검색 가능 |
| 3 | 행 클릭 시 `audit_metadata` JSONB 전체 내용 모달로 표시 | before/after diff 등 상세 컨텍스트 확인 |
| 4 | AdminShell "Security" 그룹에 메뉴 항목 추가 | 콘솔 내 자연스러운 네비게이션 동선 |
| 5 | 5 locale i18n 키 `admin.audit_logs.*` 10~15개 적용 | 기존 다국어 정책 일관성 유지 |

## 3. 백엔드 Endpoint 명세

### 3-1. GET /admin/audit-logs

```python
@router.get("/admin/audit-logs")
async def list_audit_logs(
    actor_id: UUID | None = None,
    action: str | None = None,
    target_type: str | None = None,
    target_id: UUID | None = None,
    period_start: date | None = None,
    period_end: date | None = None,
    cursor: str | None = None,   # created_at ISO-8601 기준 (DESC)
    limit: int = Query(default=50, ge=1, le=200),
    admin: User = Depends(require_admin_with_2fa),
    db: AsyncSession = Depends(get_db),
) -> AuditLogListResponse:
```

**쿼리 전략**

1. 기본 정렬: `created_at DESC` — `ix_audit_logs_created` 인덱스 활용
2. `cursor` 전달 시: `WHERE created_at < cursor::timestamptz` (keyset pagination)
3. `actor_id` 필터: `ix_audit_logs_actor` 활용
4. `action` 필터: `ix_audit_logs_action` 활용 (exact match 또는 prefix `LIKE 'admin.%'`)
5. `target_type + target_id` 복합 필터: `ix_audit_logs_target` 활용
6. `period_start / period_end`: `created_at BETWEEN` — `ix_audit_logs_created` 활용

**응답 스키마**

```python
class AuditLogItem(BaseModel):
    id: UUID
    actor_id: UUID | None
    actor_role: str | None
    action: str
    target_type: str | None
    target_id: UUID | None
    audit_metadata: dict | None   # JSONB 전체 포함 (추가 호출 불필요)
    ip_address: str | None
    user_agent: str | None
    status: str
    created_at: datetime

class AuditLogPagination(BaseModel):
    next_cursor: str | None   # 다음 페이지 cursor (created_at ISO-8601)
    has_more: bool

class AuditLogListResponse(BaseModel):
    data: list[AuditLogItem]
    pagination: AuditLogPagination
```

**민감 필드 서버 측 마스킹** (응답 직렬화 시 적용)

`audit_metadata` JSONB 내 아래 키를 `"***"` 치환:
- `password_hash`, `password`, `token`, `secret`, `recovery_code`

## 4. UI 디자인

### 4-1. 레이아웃 개요

```
┌─────────────────────────────────────────────────────────────────┐
│ AdminShell Sidebar        │  /admin/audit-logs                  │

│  - Curation               │  │ 감사 로그                    │    │
│  - ML Operations          │  │ 운영자 액션 이력 추적         │    │
│  - Security               │  └─────────────────────────────┘    │
│    > 감사 로그  ← 신규     │                                     │
│    > 패스키                │  [필터 패널 — 토글]                  │
│    > 복구 코드             │  actor | action | target | period   │
│  - System                 │                                     │
│                           │  [결과 테이블]                       │
│                           │  actor | action | target | 시간 | IP │
│                           │  ─────────────────────────────────  │
│                           │  row 클릭 → metadata 모달            │
│                           │                                     │
│                           │  [이전] [1~50 / has_more] [다음]     │
└─────────────────────────────────────────────────────────────────┘
```

### 4-2. 필터 패널

상단 "필터" 토글 버튼 클릭 시 펼쳐지는 인라인 패널 (사이드 패널 아님).
필터 변경 시 즉시 조회 (Submit 버튼 없음, 300ms debounce).

| 필터 항목 | UI 위젯 | 비고 |
|----------|---------|------|
| actor | Text input (actor 이메일 또는 이름 검색) | actor_id UUID로 변환은 백엔드 처리 또는 별도 lookup |
| action | Select dropdown | 전체 / admin.* / user.* 그룹 + 개별 action 값 |
| target_type | Select dropdown | 전체 / user / post / auction / featured_artist_candidate / ai_collection / experiment / diversity_config |
| target_id | Text input (UUID) | target_type 선택 시 활성화 |
| 기간 | DateRangePicker | 시작일 ~ 종료일 (오늘 / 7일 / 30일 / 직접 입력) |

> `actor` 필터 구현 단순화: 프론트엔드에서 actor_id(UUID)를 직접 받기 어려우므로
> 백엔드에서 `actor_id` 필터 대신 `actor_email` 문자열을 받아 서버에서 users 테이블 join 검색.
> 단, 첫 구현에서는 actor_id UUID 직접 입력으로 MVP 처리하고 OQ로 남김.

### 4-3. 결과 테이블 컬럼

| 컬럼 | 데이터 | 표시 방식 |
|------|--------|---------|
| Actor | actor_role 배지 + actor_id 앞 8자 | `admin` / `user` 색상 배지 |
| Action | action 문자열 | `admin.*` → 파란 배지, `user.*` → 회색 배지 |
| Target | target_type + target_id 앞 8자 | 없으면 `—` |
| 상태 | status | `success` 녹색, `failure` 빨간, `error` 주황 |
| IP | ip_address | 없으면 `—` |
| 시간 | created_at | `YYYY-MM-DD HH:mm` (로컬 시간) |

각 행 클릭 시 `AuditLogDetailModal` 오픈.

### 4-4. AuditLogDetailModal 구조

```
┌────────────────────────────────────────────────┐
│  감사 로그 상세                          [×]   │
├────────────────────────────────────────────────┤
│  Action:   admin.update_user                   │
│  Actor:    admin / {actor_id}                  │
│  Target:   user / {target_id}                  │
│  Status:   success                             │
│  IP:       203.0.113.42                        │
│  시간:     2026-05-08 14:32:11                 │
├────────────────────────────────────────────────┤
│  메타데이터 (audit_metadata)                    │
│  ┌──────────────────────────────────────────┐  │
│  │ {                                        │  │
│  │   "before": { "status": "active" },      │  │
│  │   "after":  { "status": "suspended" }    │  │
│  │ }                                        │  │
│  └──────────────────────────────────────────┘  │
│  [원본 보기 (5KB 초과 시)]                      │
└────────────────────────────────────────────────┘
```

- `audit_metadata`가 `null`이면 "메타데이터 없음" 표시
- JSON은 `<pre>` + 코드 블록 스타일로 포맷팅 (2 space indent)
- 5KB 초과 시 첫 5KB만 표시 + "전체 보기" 버튼

### 4-5. 페이지네이션

cursor-based. 무한 스크롤 대신 명시적 "다음 페이지" 버튼 사용 (감사 로그 특성상 특정 구간 검색이 주 패턴).

```
[이전 페이지]   현재: 1~50건   [다음 페이지 →]
```

- `has_more = false`이면 "다음 페이지" 버튼 비활성
- cursor 히스토리를 로컬 배열에 저장해 "이전 페이지" 구현

### 5-2. AuditLogShell.tsx

- `"use client"` 선언
- `fetchMe()` 호출로 admin role 확인 (FeaturedArtistQueueShell 패턴 동일)
- 인증 미완료 시 로딩 스피너, role !== "admin" 시 `/` 리다이렉트, catch 시 `/login` 리다이렉트
- 인증 완료 후 `<AuditLogFilters>` + `<AuditLogList>` 렌더링

```tsx
"use client";

import { useEffect, useState } from "react";
import { useRouter } from "next/navigation";
import { fetchMe, ApiUser } from "@/lib/api";
import { AuditLogFilters } from "./AuditLogFilters";
import { AuditLogList } from "./AuditLogList";
import type { AuditLogFilter } from "@/lib/hooks/useAuditLogs";

export function AuditLogShell() {
  const router = useRouter();
  const [authChecked, setAuthChecked] = useState(false);
  const [filter, setFilter] = useState<AuditLogFilter>({});

  useEffect(() => {
    void fetchMe()
      .then((user: ApiUser) => {
        if (user.role !== "admin") { router.replace("/"); return; }
        setAuthChecked(true);
      })
      .catch(() => router.replace("/login"));
  }, [router]);

  if (!authChecked) {
    return (
      <div className="flex items-center justify-center min-h-screen">
        <div className="text-admin-muted text-sm">로딩 중...</div>
      </div>
    );
  }

  return (
    <main className="flex-1 min-w-0 max-w-6xl mx-auto px-6 py-8">
      <div className="mb-6">
        <h1 className="text-2xl font-bold text-admin-fg">감사 로그</h1>
        <p className="text-admin-muted text-sm mt-1">운영자 액션 이력 추적</p>
      </div>
      <AuditLogFilters filter={filter} onFilterChange={setFilter} />
      <AuditLogList filter={filter} />
    </main>
  );
}
```

### 5-7. lib/api.ts 확장 (1 함수)

기존 `lib/api.ts` 하단에 추가:

```ts
export interface AuditLogListResponse {
  data: AuditLogItem[];
  pagination: {
    next_cursor: string | null;
    has_more: boolean;
  };
}

export async function fetchAuditLogs(
  params: AuditLogFilter & { cursor?: string; limit?: number }
): Promise<AuditLogListResponse> {
  const url = buildUrl("/admin/audit-logs", params);
  const res = await apiFetch(url, { method: "GET" });
  const json = await res.json();
  if (!res.ok || "error" in json) {
    throw new Error(json.error?.message ?? "감사 로그 조회 실패");
  }
  return json.data;
}
```

`buildUrl` 헬퍼: URLSearchParams로 undefined 값 자동 스킵.
