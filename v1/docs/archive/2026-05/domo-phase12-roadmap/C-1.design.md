## 1. 목표 & AC (Acceptance Criteria)

### 목표

Phase 11 D-3에서 이메일+비밀번호 가입을 구현했으나 비밀번호 재설정 플로우가 미구현으로 남아 있다. 사용자가 비밀번호를 잊었을 때 복구 수단이 없다는 치명적 UX 결함을 해소한다.

신흥 지역(동남아시아, 라틴아메리카, 동유럽) 사용자 중 이메일+비밀번호 가입자가 비밀번호를 분실해도 계정을 복구할 수 있어야 한다 (README 비전: "동유럽이든 남미든 동아시아든 — 꿈과 희망").

### OQ 결정 (Phase 12 plan 권장 default)

| 항목 | 결정 | 근거 |
|------|------|------|
| 토큰 만료 | 1시간 | 보안 우선 (D-3 이메일 인증 24시간보다 짧게) |
| 재발송 cooldown | 5분 | D-3 이메일 인증 패턴 동일 적용 |
| 1회용 토큰 | 사용 후 즉시 무효화 | used_at 기록으로 관리 |
| 잠금 계정 reset 허용 | 허용 | 비밀번호 재설정이 잠금 해제 수단이 됨 |
| 별도 테이블 | password_reset_tokens 신규 | users 컬럼 오염 방지 + 감사 추적 용이 |
| IP 기록 | 기록 (audit 목적) | plan OQ-8 권장 |

### AC

1. `POST /auth/password/reset-request` → 존재하는 이메일 시 1시간 유효 재설정 링크 발송
2. 존재하지 않는 이메일도 200 반환 (enumeration 방지)
3. Google OAuth 전용 계정 요청 시 200 + 안내 메시지 (패스워드 없음)
4. 5분 cooldown — 동일 이메일 재요청 시 429 `RESET_TOO_SOON`
5. `POST /auth/password/reset` → 토큰 검증 + 새 비밀번호 설정
6. 만료 토큰 → 400 `TOKEN_EXPIRED`
7. 사용된 토큰 → 400 `TOKEN_ALREADY_USED`
8. 비밀번호 변경 후 기존 refresh token 전체 무효화 (모든 세션 로그아웃)
9. 잠금된 계정(failed_login_count, failed_login_locked_until) 비밀번호 재설정 시 잠금 해제
10. audit_log 기록: `user.password_reset_request` / `user.password_reset_complete`
11. LoginModal "비밀번호 찾기" 링크 활성화 (D-3에서 disabled 상태)
12. i18n 5 locale (ko/en/ja/zh/es)

## 2. Database — alembic 0086

### 설계 결정: 별도 테이블 채택

D-3의 `email_verification_token`은 `users` 테이블에 컬럼으로 추가했다. password reset은 별도 `password_reset_tokens` 테이블을 신규 생성한다.

**이유**:
- `users` 테이블에 reset 컬럼 추가 시 이미 인증 관련 컬럼이 5개 — 더 늘리면 테이블 오염
- 재설정 요청 내역(IP, 발송 시각, 사용 여부)을 별도 감사 추적 가능
- 복수의 미사용 토큰 관리 가능 (재요청 시 기존 토큰 무효화 패턴 구현 용이)

### password_reset_tokens 테이블

```sql
CREATE TABLE password_reset_tokens (
    id          SERIAL PRIMARY KEY,
    user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token       VARCHAR(64) UNIQUE NOT NULL,
    ip_address  INET,
    used_at     TIMESTAMPTZ,          -- NULL = 미사용, NOT NULL = 1회 사용됨
    expires_at  TIMESTAMPTZ NOT NULL, -- 발급 시각 + 1시간
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 인덱스
CREATE UNIQUE INDEX ix_password_reset_tokens_token ON password_reset_tokens(token);
CREATE INDEX ix_password_reset_tokens_user_id_expires ON password_reset_tokens(user_id, expires_at);
```

## 3. Backend Endpoints

### 3.1 POST /auth/password/reset-request

**Request**:
```json
{ "email": "user@example.com" }
```

**비즈니스 로직**:

1. 이메일 소문자 정규화
2. `users` 테이블에서 이메일 조회
3. **이메일이 존재하지 않아도 200 반환** (enumeration 방지 — 공격자가 가입 여부 파악 불가)
4. Google OAuth 전용 계정(`password_hash IS NULL`) → 200 반환 + 내부 log warning (이메일에는 "Google 계정이므로 Google로 로그인하세요" 안내)
5. 5분 cooldown 확인 — `password_reset_tokens` 테이블에서 `user_id + created_at > now - 5min` 조회
   - 미사용 토큰 존재 → 429 `RESET_TOO_SOON` + `retry_after_seconds`
6. 기존 미사용 토큰 전체 무효화 (`used_at = now()`)
7. 토큰 생성: `secrets.token_urlsafe(32)` (43자, 256비트 엔트로피) — D-3 `generate_verification_token()` 함수 재사용
8. `PasswordResetToken` 행 INSERT (ip_address, expires_at = now + 1h)
9. 재설정 이메일 발송 (email_verification.py 패턴 재활용)
10. audit_log: `action="user.password_reset_request"`

**Response (200)**:
```json
{
  "data": {
    "sent": true,
    "message": "비밀번호 재설정 링크를 이메일로 발송했습니다."
  }
}
```

**Error 케이스**:

| 상황 | HTTP | error_code |
|------|:----:|-----------|
| 5분 cooldown 미충족 | 429 | `RESET_TOO_SOON` |
| Rate limit (10/min/IP) | 429 | `RATE_LIMITED` |

> 이메일 미존재, Google 계정 모두 200 반환 (보안 정책).

**라우터 코드 스케치** (`app/api/auth.py` 추가):

```python
@router.post("/password/reset-request")
async def request_password_reset(
    body: PasswordResetRequestBody,
    request: Request,
    db: AsyncSession = Depends(get_db),
    _rl=rate_limit("auth_login"),
):
    """비밀번호 재설정 요청.

    - 이메일 존재 확인 → 존재하지 않아도 200 (enumeration 방지)
    - sns_provider="google" + password_hash IS NULL → 200 + log warning
    - 5분 cooldown 검증 (password_reset_tokens.created_at)
    - 기존 미사용 토큰 무효화 후 신규 토큰 발급
    - audit_log: action="user.password_reset_request"
    """
    email = body.email.lower()

    result = await db.execute(select(User).where(User.email == email))
    user = result.scalar_one_or_none()

    # 이메일 미존재 또는 Google 전용 계정: 동일 200 반환 (enumeration 방지)
    if not user or not user.password_hash:
        if user and not user.password_hash:
            log.warning("password_reset_requested_for_google_account | email=%s", email)
        return {"data": {"sent": False, "message": "처리되었습니다."}}

    # 5분 cooldown 검증
    now = datetime.now(timezone.utc)
    cooldown_boundary = now - timedelta(minutes=5)
    recent = await db.execute(
        select(PasswordResetToken)
        .where(
            PasswordResetToken.user_id == user.id,
            PasswordResetToken.used_at.is_(None),
            PasswordResetToken.created_at > cooldown_boundary,
        )
        .limit(1)
    )
    if recent.scalar_one_or_none():
        wait_seconds = int(300 - (now - cooldown_boundary).total_seconds())
        raise ApiError(
            "RESET_TOO_SOON",
            f"비밀번호 재설정 메일은 5분 후 다시 요청할 수 있습니다.",
            http_status=429,
            details={"retry_after_seconds": max(wait_seconds, 0)},
        )

    # 기존 미사용 토큰 전체 무효화
    await db.execute(
        update(PasswordResetToken)
        .where(PasswordResetToken.user_id == user.id, PasswordResetToken.used_at.is_(None))
        .values(used_at=now)
    )

    # 신규 토큰 발급
    token_str = generate_verification_token()  # secrets.token_urlsafe(32) 재사용
    reset_token = PasswordResetToken(
        user_id=user.id,
        token=token_str,
        ip_address=request.client.host if request.client else None,
        expires_at=now + timedelta(hours=1),
        created_at=now,
    )
    db.add(reset_token)
    await db.commit()

    send_result = await send_password_reset_email(
        email=user.email,
        display_name=user.display_name,
        token=token_str,
    )

    await record_audit(
        db,
        actor=user,
        action="user.password_reset_request",
        metadata={"ip": request.client.host if request.client else None},
        request=request,
        status="success",
    )

    return {"data": {"sent": send_result.get("sent", False), "message": "처리되었습니다."}}
```

### 3.2 POST /auth/password/reset

**Request**:
```json
{
  "token": "abc123...",
  "new_password": "NewPass1!"
}
```

**비즈니스 로직**:

1. `password_reset_tokens` 테이블에서 `token` 조회
2. 토큰 미존재 → 400 `INVALID_RESET_TOKEN`
3. `used_at IS NOT NULL` → 400 `TOKEN_ALREADY_USED`
4. `expires_at < now` → 400 `TOKEN_EXPIRED`
5. `validate_password(new_password)` — D-3와 동일 정책 (8자+, 3종 이상)
6. bcrypt hash 생성 (cost=12, D-3 패턴 동일)
7. `user.password_hash` 갱신
8. **잠금 해제**: `user.failed_login_count = 0`, `user.failed_login_locked_until = NULL`
9. 토큰 무효화: `used_at = now`
10. **기존 refresh token 전체 무효화** — `refresh_tokens` 테이블에서 `user_id` 해당 행 revoke (모든 세션 강제 로그아웃)
11. audit_log: `action="user.password_reset_complete"`
12. 응답: `{success: true}` → 프론트엔드는 로그인 페이지로 리다이렉트 안내

**Response (200)**:
```json
{
  "data": {
    "success": true,
    "message": "비밀번호가 변경되었습니다. 새 비밀번호로 로그인해주세요."
  }
}
```

**Error 케이스**:

| 상황 | HTTP | error_code |
|------|:----:|-----------|
| 토큰 미존재 | 400 | `INVALID_RESET_TOKEN` |
| 이미 사용된 토큰 | 400 | `TOKEN_ALREADY_USED` |
| 만료 토큰 | 400 | `TOKEN_EXPIRED` |
| 비밀번호 정책 미충족 | 422 | `PASSWORD_TOO_SHORT` / `PASSWORD_WEAK` |

**라우터 코드 스케치**:

```python
@router.post("/password/reset")
async def reset_password(
    body: PasswordResetBody,
    request: Request,
    db: AsyncSession = Depends(get_db),
):
    """비밀번호 재설정 토큰 검증 + 새 비밀번호 설정.

    - 토큰 조회 → used_at / expires_at 검증
    - validate_password (D-3 동일 정책)
    - bcrypt hash 갱신
    - 잠금 해제 (failed_login_count=0, failed_login_locked_until=NULL)
    - used_at 기록 + refresh_tokens 전체 revoke
    - audit_log: action="user.password_reset_complete"
    """
    result = await db.execute(
        select(PasswordResetToken).where(PasswordResetToken.token == body.token)
    )
    reset_token = result.scalar_one_or_none()

    if not reset_token:
        raise ApiError("INVALID_RESET_TOKEN", "유효하지 않은 재설정 토큰입니다.", http_status=400)

    if reset_token.used_at is not None:
        raise ApiError("TOKEN_ALREADY_USED", "이미 사용된 재설정 토큰입니다.", http_status=400)

    now = datetime.now(timezone.utc)
    if reset_token.expires_at < now:
        raise ApiError("TOKEN_EXPIRED", "재설정 링크가 만료되었습니다. 새로 요청해주세요.", http_status=400)

    validate_password(body.new_password)

    result = await db.execute(select(User).where(User.id == reset_token.user_id))
    user = result.scalar_one()

    # 새 비밀번호 해시 + 잠금 해제
    user.password_hash = hash_password(body.new_password)
    user.failed_login_count = 0
    user.failed_login_locked_until = None

    # 토큰 무효화
    reset_token.used_at = now

    # 기존 refresh token 전체 무효화 (모든 세션 강제 로그아웃)
    await db.execute(
        update(RefreshToken)
        .where(RefreshToken.user_id == user.id, RefreshToken.revoked_at.is_(None))
        .values(revoked_at=now, revoked_reason="password_reset")
    )

    await db.commit()

    await record_audit(
        db,
        actor=user,
        action="user.password_reset_complete",
        metadata={"ip": request.client.host if request.client else None},
        request=request,
        status="success",
    )

    return {"data": {"success": True, "message": "비밀번호가 변경되었습니다. 새 비밀번호로 로그인해주세요."}}
```

## 6. 보안 검증

### 6.1 토큰 보안

| 항목 | 구현 | 근거 |
|------|------|------|
| 토큰 생성 | `secrets.token_urlsafe(32)` = 43자 (256비트) | D-3와 동일, 브루트포스 불가 |
| 만료 시간 | 1시간 | 이메일 인증(24시간)보다 짧게 (재설정은 고위험 작업) |
| 1회용 | `used_at IS NOT NULL` 검사 | 재사용 공격 차단 |
| 재발급 시 기존 무효화 | `used_at = now()` 일괄 처리 | 다중 토큰 동시 유효 방지 |
| DB 저장 | 평문 저장 (단일 사용 후 무효화) | D-3 이메일 인증 패턴 동일 |

### 6.2 Enumeration 방지

`POST /auth/password/reset-request`는 이메일 존재 여부와 무관하게 항상 200을 반환한다. 응답 바디의 `sent` 필드도 외부에서 구분 불가하도록 `false`일 때도 `"처리되었습니다."` 메시지를 반환한다.

### 6.3 Cooldown

5분 cooldown은 `password_reset_tokens.created_at`으로 계산한다. 429 응답에는 `retry_after_seconds`를 포함해 프론트엔드에서 카운트다운 표시 가능.

### 6.4 잠금 계정 해제 정책

`failed_login_count >= 5`로 잠긴 계정이 비밀번호 재설정을 완료하면:
- `user.failed_login_count = 0`
- `user.failed_login_locked_until = NULL`

비밀번호를 재설정했다는 것은 계정 소유권을 이메일로 인증한 것이므로 잠금 해제가 합리적이다.

### 6.5 세션 무효화

비밀번호 변경 후 기존 refresh token 전체를 `revoked_reason="password_reset"`으로 revoke한다. 공격자가 탈취한 세션을 즉시 차단하는 효과.

### 6.6 Rate Limit

`POST /auth/password/reset-request`는 기존 `auth_login` rate limit 키 적용 (IP 기준 10/min). 추가적으로 5분 cooldown이 사용자 단위 2차 방어선.
